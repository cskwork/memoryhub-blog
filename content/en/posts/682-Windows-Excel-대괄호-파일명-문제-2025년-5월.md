A serious issue has emerged in Excel filenames containing brackets due to Microsoft Office's May 2025 security update. This is not simply a bug but a complex problem resulting from the combination of Microsoft's design decisions and recent security enhancements.

## Major Change in May 2025: Impact of Office Security Update

The **most significant finding** is that Microsoft Office's May 13, 2025 security update (KB5002717 and related patches) has begun completely blocking filenames containing brackets in Office 2016, Office 2016-2021 C2R, Office 2021, and Microsoft 365.

According to a report from Germany's Dennis F. on May 23, 2025, Excel now **truncates** filenames at brackets and processes them. For example, with a file named `[Test]Report.xlsx`, Excel attempts to find only `Report.xlsx` instead of the entire filename. This was confirmed in Office 365 Version 2504 Build 16.0.18730.20186 and Version 2505 Build 16.0.18827.20102, and interestingly, the issue does not occur on Office 2016 32-bit MSI version on Windows 10 22H2.

## Fundamental Technical Cause: Excel's Design Limitations

Excel's bracket issue stems from **design constraints that have persisted since the 1990s**. Excel uses brackets as syntax delimiters for external workbook references (`=[WorkbookName.xlsx]SheetName!CellReference`). This causes Excel to experience a **fundamental parsing conflict** where it cannot distinguish between brackets that are part of the filename and brackets in formula syntax.

Microsoft officially classifies this as "expected behavior, not a bug." According to Microsoft support documentation, characters such as `< > ? [ ] : | *` are **prohibited characters** in Excel workbook filenames, and particularly in files containing pivot tables cause "Invalid Data Source Reference" errors.

## Specific Impact of Windows and Office Updates

### November 2024 Excel Security Update as a Precursor

On November 12, 2024, an Excel security update (KB5002653) fixed **five Excel remote code execution vulnerabilities from CVE-2024-49026 through CVE-2024-49030**. This update directly modified Excel's file opening mechanism and affected how files with special characters are processed.

### Windows 11 24H2 Security Hardening

Starting October 1, 2024, the gradually rolled-out Windows 11 24H2 introduced **SMB signature requirement enabled by default** and **enhanced file system security**. Updates KB5044284 (October 8), KB5046617 (November 12), and KB5048667 (December 10) particularly significantly strengthened file handling security.

### Microsoft Defender and Edge Security Policy Changes

Microsoft Defender's October-November 2024 platform updates introduced **more aggressive file scanning algorithms**, and the "suspicious filename pattern" detection feature was enhanced. Microsoft Edge's improved SmartScreen began more strictly classifying and automatically blocking files containing special characters.

## Browser-Specific Behavioral Differences and Download Issues

### Internet Explorer's Unique Problem

Internet Explorer automatically appends `[1]`, `[2]`, etc. to filenames when downloading duplicates. This **completely disables pivot table auto-refresh functionality** and causes errors like "file[1].yourPivotTableName is not valid."

### Relative Stability of Modern Browsers

Chrome, Edge (Chromium), and Firefox largely preserve original filenames passed through the Content-Disposition header. Firefox provides **the strongest Unicode support**, while Chrome and Edge show quote-related issues in specific scenarios, but handle brackets well.

## Serious Impact in Enterprise Environments

One user reported: "A legacy system written in COBOL automatically generates files with brackets. Older Office versions can still access these files, but users with 365 cannot."

**Problems faced by enterprise IT administrators:**

- Inability to access existing files generated by legacy systems
- Email attachments automatically have duplicate numbers added in brackets
- Interruption of automated reporting systems
- Inaccessibility of existing files on shared drives

## Practical Solutions and Workarounds

### Immediately Applicable Temporary Solutions

1. **Rename files**: Remove all brackets and then open in Excel
2. **Browser settings**: Use "Save" instead of "Open" when downloading via IE
3. **Switch browsers**: Use Chrome, Firefox, or Edge instead of IE
4. **Manual file copy**: Save file to desktop and rename

### System-Level Solutions for IT Administrators

1. **Group Policy**: Implement naming rules prohibiting bracket usage
2. **File server scripts**: Automatically rename files containing brackets
3. **Browser configuration**: Exclude IE from defaults for Office file handling
4. **Version management**: Maintain older Office versions for legacy file access

### Fundamental Solutions for Developers

**Server-side solutions:**

- Set Content-Disposition header to "attachment" instead of "inline"
- Pre-remove brackets from filenames
- Prevent bracket generation through URL rewriting

**Client-side solutions:**

- Automatically rename downloaded files through file system watcher
- Detect and handle brackets through VBA macro
- Automated file processing through .NET application

## Microsoft's Official Position and Future Outlook

Microsoft regards this as **"behavior outside of Excel specifications"** and recommends users comply with file naming conventions rather than fixing the bug. Official Microsoft support documentation clearly classifies brackets as "invalid characters" and recommends their removal.

**OneDrive and Microsoft 365 Integration:**  
Microsoft 365 apps **automatically rename files** containing brackets when saving to OneDrive. This demonstrates that Microsoft consistently treats brackets as unsupported characters.

## Conclusion: Recommendations for Fundamental Resolution

This issue is not a simple technical bug but a **fundamental architectural design limitation of Excel**. While the May 2025 security update has exacerbated the problem, this is a continuation of design constraints that have persisted for over 30 years.

**Recommendations for organizations:**

1. **Short-term**: Immediately implement file naming policy excluding brackets
2. **Medium-term**: Fix legacy system file generation logic
3. **Long-term**: Reduce Excel dependency and evaluate alternative solutions

**Recommendations for developers:**

1. Prohibit bracket usage when creating files on servers
2. Optimize Content-Disposition header
3. Implement filename validation and sanitization logic on client side

**Final Assessment**: Since Microsoft classifies this as intended behavior, the possibility of future fixes is low. Organizations and developers should realistically adjust their systems to comply with Excel's filename constraints. Due to the May 2025 security update making the issue more strict, bulk renaming of existing files and adoption of new naming conventions are urgent.
