A generalized e-commerce database design that **fully replicates Coupang's SKU-centric product management system**. It can represent all product types including MacBooks, apparel, food, and electronics, and accurately implements the core concept of **SKU creation through option combination**.

## Table Descriptions

### 1. Category (Category)

**Purpose**: Manage hierarchical classification system of products

**Key Columns**:

- `category_id`: Category unique identifier
- `category_name`: Category name (e.g., "Laptops", "MacBook")
- `parent_category_id`: Reference to parent category (self-referential structure)
- `category_level`: Hierarchy depth (1=primary, 2=secondary, 3=tertiary)
- `slug`: URL-friendly identifier
- `display_order`: Sort order within the same level

**Characteristics**:

- **Self-referential** structure supports infinite hierarchy
- Root categories have `parent_category_id = NULL`
- Recursive queries (Recursive CTE) can be used for tree traversal

**Example Data**:

```
category_id | category_name         | parent_id | level
1           | Electronics           | NULL      | 1
10          | Laptops/Desktops      | 1         | 2
101         | Laptops               | 10        | 3
1011        | MacBook               | 101       | 4
```

---

### 2. Brand (Brand)

**Purpose**: Manage manufacturer/brand information

**Key Columns**:

- `brand_id`: Brand unique identifier
- `brand_name`: Brand name (e.g., "Apple", "Samsung")
- `brand_logo_url`: Brand logo image URL
- `description`: Brand description

**Characteristics**:

- Supports product filtering by brand
- Enables brand page composition
- UNIQUE constraint recommended on `brand_name`

---

### 3. Product (Product)

**Purpose**: Manage basic product information (common info independent of options)

**Key Columns**:

- `product_id`: Product unique identifier (Coupang's Product ID)
- `category_id`: Belonging category
- `brand_id`: Brand
- `product_name`: Product name (e.g., "Apple MacBook Air 13 M1")
- `description`: Detailed product description
- `thumbnail_image_url`: Representative thumbnail
- `slug`: SEO-friendly URL
- `status`: Sales status (on_sale, discontinued, pending)

**Characteristics**:

- **Stores only common information independent of options**
- Price and inventory are managed at SKU level
- One Product has multiple SKUs (variants)

**Example Data**:

```
product_id: 4322481134
product_name: "Apple MacBook Air 13 M1"
category_id: 1011
brand_id: 5
status: "on_sale"
```

---

### 4. Property (Attribute/Option Type)

**Purpose**: Define **option types** that products can have (generic)

**Key Columns**:

- `property_id`: Attribute type unique identifier
- `property_name`: Attribute name (e.g., "Color", "Memory", "Storage", "Size")
- `property_type`: Input type (dropdown, text, number, unit)
- `input_unit`: Unit (GB, TB, cm, kg, etc.)
- `is_required`: Required flag

**Characteristics**:

- **Generic attribute pool independent of categories**
- Different attributes apply to different categories: apparel has "Color, Size", electronics have "Color, Capacity"
- Reflects Coupang's strict unit notation rules (`input_unit` field)

**Example Data**:

```
property_id | property_name | property_type | input_unit
1           | Color         | dropdown      | NULL
2           | Memory        | unit          | GB
3           | Storage       | unit          | GB
4           | Size          | dropdown      | NULL
5           | Weight        | unit          | kg
```

---

### 5. PropertyAttribute (Attribute Values)

**Purpose**: Define **specific values** that each attribute type can have

**Key Columns**:

- `attribute_id`: Attribute value unique identifier
- `property_id`: Belonging attribute type
- `attribute_value`: Actual value (e.g., "Silver", "16GB", "256GB")
- `display_name`: Name for display on screen
- `additional_price`: Additional amount when this option is selected (nullable)
- `display_order`: Sort order

**Characteristics**:

- **Master data for option values**
- `additional_price` is an additional amount compared to base price (optional)
- Often uses independent price per SKU in practice

**Example Data**:

```
attribute_id | property_id | attribute_value | additional_price
10           | 1           | Silver          | 0
11           | 1           | Space Gray      | 0
12           | 1           | Gold            | 0
20           | 2           | 8GB             | 0
21           | 2           | 16GB            | 200000
30           | 3           | 256GB           | 0
31           | 3           | 512GB           | 300000
32           | 3           | 1TB             | 600000
```

---

### 6. ProductProperty (Product-Attribute Connection)

**Purpose**: Define **which attributes a specific product has**

**Key Columns**:

- `product_property_id`: Connection unique identifier
- `product_id`: Target product
- `property_id`: Attribute type to apply
- `is_variant_defining`: Does this attribute distinguish SKUs? (important!)
- `display_order`: Option display order

**Characteristics**:

- **Different attribute combinations per product**
- Combinations of attributes with `is_variant_defining=true` create SKUs
- Example: MacBook has "Color, Memory, Storage" / Apparel has "Color, Size"

**Example Data**:

```
product_property_id | product_id   | property_id | is_variant_defining | display_order
1                   | 4322481134   | 1 (Color)   | true                | 1
2                   | 4322481134   | 2 (Memory)  | true                | 2
3                   | 4322481134   | 3 (Storage) | true                | 3
```

---

### 7. SKU (Stock Keeping Unit) ⭐ Core Table

**Purpose**: **Manage price, inventory, and status of actual option combinations** sold

**Key Columns**:

- `sku_id`: SKU unique identifier
- `product_id`: Belonging product
- `sku_code`: External identification code (Unique, e.g., "72804430234")
- `item_id`: Coupang internal system ID
- `base_price`: Regular price (before discount)
- `selling_price`: Selling price (actual customer payment)
- `discount_rate`: Discount rate (%)
- `stock_quantity`: Current stock quantity
- `low_stock_threshold`: Criterion for low stock alert (default: 9)
- `status`: Sales status (available, out_of_stock, low_stock, discontinued)

**Characteristics**:

- **One SKU per option combination**
- Price and inventory are **independently managed at SKU level**
- `sku_code` is Unique Index for fast lookup
- Low stock logic: `stock_quantity <= low_stock_threshold`

**Example Data**:

```
sku_id | product_id   | sku_code      | base_price | selling_price | stock_qty | status
1      | 4322481134   | 72804430234   | 1360000    | 1169360       | 25        | available
2      | 4322481134   | 72804430326   | 1380000    | 1185600       | 18        | available
3      | 4322481134   | 5504842557    | 1780000    | 1546150       | 8         | low_stock
4      | 4322481134   | 5504848475    | 2100000    | 1795200       | 0         | out_of_stock
```

---

### 8. SKUAttribute (SKU-Attribute Mapping) ⭐ Core Table

**Purpose**: Define **how SKU is composed from which option combinations**

**Key Columns**:

- `sku_attribute_id`: Mapping unique identifier
- `sku_id`: Target SKU
- `property_id`: Attribute type (Color, Memory, etc.)
- `attribute_id`: Selected attribute value (Silver, 16GB, etc.)

**Characteristics**:

- **This table is the core of the SKU system!**
- One SKU has multiple attribute values (many-to-many relationship)
- Option combinations dynamically compose SKUs

**Business Logic**:

```
SKU 1 (MacBook Air Silver 16GB 256GB):
  - attribute_id: 10 (Silver) ← property_id: 1 (Color)
  - attribute_id: 21 (16GB) ← property_id: 2 (Memory)
  - attribute_id: 30 (256GB) ← property_id: 3 (Storage)

SKU 2 (MacBook Air Space Gray 16GB 256GB):
  - attribute_id: 11 (Space Gray) ← property_id: 1
  - attribute_id: 21 (16GB) ← property_id: 2
  - attribute_id: 30 (256GB) ← property_id: 3
```

**Example Data**:

```
sku_attribute_id | sku_id | property_id | attribute_id
1                | 1      | 1           | 10  (Color: Silver)
2                | 1      | 2           | 21  (Memory: 16GB)
3                | 1      | 3           | 30  (Storage: 256GB)
4                | 2      | 1           | 11  (Color: Space Gray)
5                | 2      | 2           | 21  (Memory: 16GB)
6                | 2      | 3           | 30  (Storage: 256GB)
7                | 3      | 1           | 12  (Color: Gold)
8                | 3      | 2           | 21  (Memory: 16GB)
9                | 3      | 3           | 31  (Storage: 512GB)
```

### 9. ProductImage (Product Images)

**Purpose**: Manage product and option-specific images

**Key Columns**:

- `image_id`: Image unique identifier
- `product_id`: Belonging product
- `attribute_id`: Connection to specific option (nullable, e.g., color-specific image)
- `image_url`: Image URL (CDN path recommended)
- `image_type`: Image type (thumbnail, detail, description)
- `display_order`: Image order
- `is_primary`: Primary image flag

**Characteristics**:

- **Product level**: Common images (`attribute_id = NULL`)
- **Variant level**: Color-specific images (`attribute_id = 10 (Silver)`)
- `image_type` distinguishes usage

**Example Data**:

```
image_id | product_id | attribute_id | image_type  | image_url                      | is_primary
1        | 4322481134 | NULL         | description | /img/macbook-spec.jpg          | false
2        | 4322481134 | 10 (Silver)  | thumbnail   | /img/macbook-silver-thumb.jpg  | true
3        | 4322481134 | 10 (Silver)  | detail      | /img/macbook-silver-front.jpg  | false
4        | 4322481134 | 11 (Gray)    | thumbnail   | /img/macbook-gray-thumb.jpg    | false
```

### 10. Seller (Seller)

**Purpose**: Manage seller/vendor information

**Key Columns**:

- `seller_id`: Seller unique identifier
- `seller_name`: Seller name
- `vendor_id`: External vendor ID
- `contact_number`: Contact number
- `business_registration_number`: Business registration number
- `rating`: Seller rating

**Characteristics**:

- Distinguish Coupang direct purchase vs. marketplace sellers
- Multiple sellers can sell the same product (via ProductSeller)

---

### 11. ProductSeller (Product-Seller Mapping)

**Purpose**: Manage many-to-many relationship between products and sellers

**Key Columns**:

- `product_seller_id`: Mapping unique identifier
- `product_id`: Product
- `seller_id`: Seller
- `is_primary_seller`: Primary seller flag

**Characteristics**:

- Same product can be sold by multiple sellers competitively
- Enables price comparison feature

---

### 12. Shipping (Shipping Information)

**Purpose**: Manage shipping options per SKU

**Key Columns**:

- `shipping_id`: Shipping information unique identifier
- `sku_id`: Target SKU
- `shipping_method`: Shipping method (rocket, standard, vendor)
- `shipping_fee`: Shipping cost
- `free_shipping_threshold`: Free shipping threshold amount
- `estimated_days`: Estimated delivery days (0=same day, 1=next day)
- `return_fee`: Return shipping fee
- `remote_area_available`: Remote area shipping availability

**Characteristics**:

- Different shipping conditions possible per SKU
- Distinguishes premium shipping like "Rocket Shipping"

---

### 13. Discount (Discount)

**Purpose**: Manage discount promotions per SKU

**Key Columns**:

- `discount_id`: Discount unique identifier
- `sku_id`: Target SKU
- `discount_type`: Discount type (percentage, fixed_amount, coupon)
- `discount_value`: Discount value (%, amount)
- `start_date`, `end_date`: Discount period
- `min_purchase_quantity`: Minimum purchase quantity

**Characteristics**:

- Manage time-limited discounts
- `selling_price` is the final price after discount applied

---

### 14. StockHistory (Stock History)

**Purpose**: Track inventory changes and provide audit trail

**Key Columns**:

- `history_id`: History unique identifier
- `sku_id`: Target SKU
- `quantity_change`: Change amount (+10, -5)
- `quantity_after`: Inventory after change
- `change_type`: Change type (purchase, return, adjustment, order)
- `reference_id`: Reference ID (order number, etc.)

**Characteristics**:

- Ensures inventory traceability
- Enables inventory shortage prediction analysis

## Relationship Descriptions

### 1:N Relationships

| Parent Table | Child Table | Description |
| --- | --- | --- |
| Category | Category | Self-reference: Parent category - Child category |
| Category | Product | One category contains multiple products |
| Brand | Product | One brand produces multiple products |
| Product | SKU | **One product has multiple option combinations (SKUs)** |
| Product | ProductProperty | One product has multiple attribute types |
| Product | ProductImage | One product has multiple images |
| Property | PropertyAttribute | One attribute type has multiple attribute values |
| SKU | SKUAttribute | **One SKU is composed of multiple attribute values** |
| SKU | Shipping | One SKU has one shipping information (1:1 relationship) |
| SKU | Discount | One SKU can have multiple discount policies |
| SKU | StockHistory | One SKU has multiple stock change history |

### N:M Relationships (Using Junction Tables)

| Table A | Junction Table | Table B | Description |
| --- | --- | --- | --- |
| Product | ProductProperty | Property | Product has multiple attributes, attribute is used by multiple products |
| Product | ProductSeller | Seller | Product is sold by multiple sellers, seller sells multiple products |
| SKU | SKUAttribute | PropertyAttribute | **SKU is composed of multiple attribute values, attribute value is used by multiple SKUs** |

## Key Business Logic

### 1. SKU Creation Logic

**Scenario**: Add a new option combination to MacBook Air M1

```
-- Step 1: Confirm Product
SELECT * FROM Product WHERE product_id = 4322481134;

-- Step 2: Check attributes for Product
SELECT pp.*, pr.property_name 
FROM ProductProperty pp
JOIN Property pr ON pp.property_id = pr.property_id
WHERE pp.product_id = 4322481134 AND pp.is_variant_defining = true;
-- Result: Color(1), Memory(2), Storage(3)

-- Step 3: Create new SKU (Gold + 16GB + 1TB)
INSERT INTO SKU (product_id, sku_code, base_price, selling_price, stock_quantity, status)
VALUES (4322481134, 'NEW-SKU-12345', 2180000, 1999000, 50, 'available');
-- sku_id: 5 (auto-generated)

-- Step 4: Map SKU to attribute values
INSERT INTO SKUAttribute (sku_id, property_id, attribute_id) VALUES
(5, 1, 12),  -- Color: Gold
(5, 2, 21),  -- Memory: 16GB
(5, 3, 32);  -- Storage: 1TB

-- Step 5: Set shipping information
INSERT INTO Shipping (sku_id, shipping_method, shipping_fee, estimated_days)
VALUES (5, 'rocket', 0, 1);
```

### 2. Stock Reduction Logic (on Order)

```
-- Order quantity: 2
SET @sku_id = 1;
SET @order_qty = 2;

-- Step 1: Check inventory
SELECT stock_quantity FROM SKU WHERE sku_id = @sku_id FOR UPDATE;
-- 25 (sufficient stock)

-- Step 2: Reduce inventory
UPDATE SKU 
SET stock_quantity = stock_quantity - @order_qty,
    status = CASE 
        WHEN (stock_quantity - @order_qty) = 0 THEN 'out_of_stock'
        WHEN (stock_quantity - @order_qty) <= low_stock_threshold THEN 'low_stock'
        ELSE 'available'
    END
WHERE sku_id = @sku_id;

-- Step 3: Record inventory history
INSERT INTO StockHistory (sku_id, quantity_change, quantity_after, change_type, reference_id)
VALUES (@sku_id, -2, 23, 'order', 'ORDER-20251103-001');
```

### 3. Available Option Selection Query

**Scenario**: User selects "Color: Silver" → What memory options are available?

```
SELECT DISTINCT 
    pa.attribute_id,
    pa.attribute_value,
    MIN(s.selling_price) as min_price,
    SUM(s.stock_quantity) as total_stock
FROM SKU s
JOIN SKUAttribute sa1 ON s.sku_id = sa1.sku_id
    AND sa1.property_id = 1 AND sa1.attribute_id = 10  -- Color: Silver
JOIN SKUAttribute sa2 ON s.sku_id = sa2.sku_id
    AND sa2.property_id = 2  -- Memory attribute
JOIN PropertyAttribute pa ON sa2.attribute_id = pa.attribute_id
WHERE s.product_id = 4322481134
    AND s.status IN ('available', 'low_stock')
    AND s.stock_quantity > 0
GROUP BY pa.attribute_id, pa.attribute_value
ORDER BY min_price;

-- Result:
-- 8GB  | 999,000 won | 15 in stock
-- 16GB | 1,169,360 won | 25 in stock
```

### 4. Low Stock Alert Query

```
SELECT 
    p.product_name,
    s.sku_code,
    GROUP_CONCAT(
        CONCAT(pr.property_name, ': ', pa.attribute_value)
        SEPARATOR ', '
    ) as options,
    s.stock_quantity,
    s.selling_price
FROM SKU s
JOIN Product p ON s.product_id = p.product_id
JOIN SKUAttribute sa ON s.sku_id = sa.sku_id
JOIN PropertyAttribute pa ON sa.attribute_id = pa.attribute_id
JOIN Property pr ON pa.property_id = pr.property_id
WHERE s.stock_quantity <= s.low_stock_threshold
    AND s.stock_quantity > 0
    AND s.status = 'low_stock'
GROUP BY s.sku_id;
```

### 5. Category Tree Query (Recursive CTE)

```
WITH RECURSIVE CategoryTree AS (
    -- Root nodes
    SELECT 
        category_id, 
        category_name, 
        parent_category_id,
        category_level,
        CAST(category_name AS CHAR(1000)) as path
    FROM Category
    WHERE parent_category_id IS NULL

    UNION ALL

    -- Recursion: Child nodes
    SELECT 
        c.category_id,
        c.category_name,
        c.parent_category_id,
        c.category_level,
        CONCAT(ct.path, ' > ', c.category_name)
    FROM Category c
    JOIN CategoryTree ct ON c.parent_category_id = ct.category_id
)
SELECT * FROM CategoryTree ORDER BY path;

-- Result:
-- Electronics
-- Electronics > Laptops/Desktops
-- Electronics > Laptops/Desktops > Laptops
-- Electronics > Laptops/Desktops > Laptops > MacBook
```

## Core Design Points

### ✅ SKU-Centric Design

- **Product**: Common information (brand, category, description)
- **SKU**: Actual sales unit (price, inventory, status)
- **SKUAttribute**: Option combination definition

### ✅ EAV Pattern Usage

- **Property**: Generic attribute type pool
- **PropertyAttribute**: Attribute value master data
- **ProductProperty**: Product-attribute connection
- Flexibly supports different option combinations per category

### ✅ Scalability

- No schema changes needed when adding new product categories
- Just add Property/PropertyAttribute
- Same structure represents apparel, food, appliances, etc.

### ✅ Normalization

- Minimize duplicate data
- Attribute value reuse (multiple products can share "Silver")
- Data integrity guarantee

### ✅ Performance Optimization

- `sku_code` Unique Index
- `(sku_id, attribute_id)` Composite Index
- View creation recommended for frequently accessed data
- Redis caching strategy

### 2. Triggers (Automation)

```
-- Automatically change status when stock becomes 0
DELIMITER $$
CREATE TRIGGER trg_update_sku_status_on_stock
BEFORE UPDATE ON SKU
FOR EACH ROW
BEGIN
    IF NEW.stock_quantity = 0 THEN
        SET NEW.status = 'out_of_stock';
    ELSEIF NEW.stock_quantity <= NEW.low_stock_threshold THEN
        SET NEW.status = 'low_stock';
    ELSE
        SET NEW.status = 'available';
    END IF;
END$$
DELIMITER ;
```

### 3. Useful Views

```
-- SKU detail information view
CREATE VIEW v_sku_detail AS
SELECT 
    s.sku_id,
    s.sku_code,
    p.product_id,
    p.product_name,
    b.brand_name,
    s.selling_price,
    s.stock_quantity,
    s.status,
    GROUP_CONCAT(
        CONCAT(pr.property_name, ': ', pa.attribute_value)
        ORDER BY pr.display_order
        SEPARATOR ' / '
    ) as option_combination
FROM SKU s
JOIN Product p ON s.product_id = p.product_id
JOIN Brand b ON p.brand_id = b.brand_id
JOIN SKUAttribute sa ON s.sku_id = sa.sku_id
JOIN PropertyAttribute pa ON sa.attribute_id = pa.attribute_id
JOIN Property pr ON pa.property_id = pr.property_id
GROUP BY s.sku_id;
```
