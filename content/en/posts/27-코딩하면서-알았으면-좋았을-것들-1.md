1. For all data to exist, it must have an **address**, a name, type, and size. The address is the hardest to visualize, so you always need to keep track of where and how it came from. Sometimes you can click on a class while holding Ctrl to verify how it was created.

2. When reading code, move **from macro to micro** - look at parameters and return values first, then the logic.

3. Before building anything initially, identify which CRUD operation you'll perform, determine the conditions that trigger each CRUD operation, choose what values to CRUD, and start by accurately sending/receiving **only the values** you intend to transmit using a very simple form (ignore tables and use just input tags).

4. If there's an <input name=""> tag, when sending values, the name becomes the key value and the value inside the input tag becomes the value. This **key-value mapping** is sometimes stored under another key called "map" (when using DTO as commandMap).

5. For select or update (for delete purposes), the values received from the form are usually the **IDX** (i.e., UNIQUE KEY value). You don't need to pass all values as parameters since you can fetch other data using this value in SQL.

6. Insert and update don't require return values. You're just writing to the database, so the return in the service and dao layers is **null**.

7. Configuration is very important. Check if you've imported the necessary tools, if you're using the correct **URI**, if you've distinguished between the form URI and the actual action URI and made requests with the matching URI, if the interceptor is added to the desired path, if the viewResolver's prefix/suffix matches the specified path, etc.

8. For NULL cases, verify that data was actually input correctly, check the database, and write conditions in SQL to handle null data if you're loading it anyway. Check all data type, size, and field names.

9. When errors occur, check the console first, **see the data with your own eyes**, check the path, and analyze whether you understand the code correctly. (Sometimes it's a tool issue, so try cleaning to clear the cache).

10. Without fail, **back up** your code via RAR every time a feature is implemented.

11. If code doesn't make sense at first, keep reading it again and again to become **familiar** with it, verify it visually, and repeat.

12. Proper **rest** is really important.

13. The more confused and stuck you are, the **slower** you should go and approach step by step.
