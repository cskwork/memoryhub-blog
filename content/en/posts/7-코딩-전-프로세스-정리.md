**Web Request/Response Process**

- You must have the fundamental web process in mind. Spring operates everything centered on Dispatcher Servlet, and first as a basic web request framework,
- You must recognize the client-server and user-provider structure,
- When a user initially makes a web request (for example, calling a READ/SELECT query to read data stored on the server via the web), the request goes through the servlet,
- which maps the requested URI to the corresponding Controller (this mapping means connecting to the bean already instantiated in the WAS at the Spring server level, meaning controller, service, resource modules are already registered via component scan),
- Once connected to the Controller from the request, the Controller receives user requests as parameter values and executes the necessary ServiceImpl (performs necessary functions). ServiceImpl typically inherits from Service Interface (summarized so developers can see all functions at a glance) and is implemented accordingly, so the method in ServiceImpl is executed.
- When you see the connected ServiceImpl, hold Ctrl and click on the corresponding class with your mouse, and you'll be taken to the implemented method.
- Moving to the method, if it inherited from Service Interface, there will be an @Override annotation. Leave that as is and check what parameters ServiceImpl receives and what return values it implements.
- ServiceImpl will also be using methods from DAO (Data Access Object), objects that access data (DB).
- DAO uses mapper namespace (namespace for mapper identification) and will use QueryId as parameters, and here **sql.xml file connection is made.
- **sql.xml files are usually located in src/resource and execute CRUD operations (Create- insert to create, Read- select to read, Update- update to modify, Delete - update to 'Y' in del column) to access the DB through query implementation.
