You might think coding is just about making something work, right? Of course, at first it is! But the code we write is a valuable asset that we'll continue to fix and share with others. Like building a house, the process requires first setting up the structure (Make It Work), passing safety standards (Make It Right), and finally adding nice interior design (Clean It Up). Today, let's explore this 3-step process and learn how to write better, more efficient code!

## Background

These days, many people still write code with a focus only on implementing features. "Let's just make it work!" was the mindset. But while this approach might be fast initially, it creates serious difficulties when modifying code or adding features later. Code becomes tangled and complex, making it hard to know where to fix things, and often unexpected bugs appear when you try to make changes.

To solve these problems and create code that's easy to maintain long-term and good for collaborating with other developers, the importance of 'clean code' emerged, proposing a systematic approach: "Make It Work -> Make It Right -> Clean It Up".

## The 3-Step Clean Code Process Solves These Problems:

1. **Problem 1: The code doesn't work at all!**
   - **Solution (Make It Work):** Focus on making the code perform its basic function. It doesn't have to be perfect!
2. **Problem 2: The code runs... but something feels unsafe (hidden bugs, insufficient exception handling)**
   - **Solution (Make It Right):** Write test code to verify your code works correctly in various scenarios (normal cases, exceptional cases). Find hidden bugs and increase code reliability.
3. **Problem 3: The code is too complex to understand and hard to modify**
   - **Solution (Clean It Up):** Refactor the working and validated code to make it more readable and maintainable. Eliminate duplication and rename variables and functions for clarity.

## Core Principles

This 3-step process can be visualized as follows:

```
+-------------------+      +-----------------+      +-----------------+
|   Step 1:         |----->|  Step 2:        |----->|  Step 3:        |
|   Make It Work    |      |  Make It Right  |      |  Clean It Up    |
| (Function focus)  |      | (Test validation)|      | (Refactoring)   |
+-------------------+      +-----------------+      +-----------------+
       |                      ^      |                      ^
       |                      |      |                      |
       +----(Record issues)---+      +----(Tests pass?)-----+
```

Let's look at each step in more detail:

**Step 1: Make It Work (Just get it working!)** 

- **Core Goal:** Quickly implement the main functionality of the code.
- **Focus on the Feature:** Don't try too hard to find the perfect or most efficient approach from the start. Your top priority is making the intended feature work!
- **Avoid Premature Optimization:** Even if you think "This part could be faster later...", skip it for now. Optimizing code that doesn't even work yet is pointless.
- **Use a To-Do List:** When writing code and you notice areas that need improvement later (like extracting specific code into a helper function or replacing hardcoded strings with constants), jot them down in comments or a separate list.
- **Don't Get Sidetracked:** Be careful not to get caught up in refactoring while implementing features. Right now, focus only on implementing!
- **Analogy:** It's like building a house - first you set up the pillars and put on the roof. Worry about interior design later.

**Step 2: Make It Right (Do it right!)**

- **Core Goal:** Validate through testing that your code works *correctly*.
- **Write Test Code:** Instead of just thinking "It should work fine", create tests that confirm your code works exactly as intended. Cover various scenarios including success cases, failure cases, and edge cases.
- **(Advanced) Use Mutation Testing:** One way to improve test code quality. Deliberately make small changes (mutations, like changing conditions) to the code, then check if existing tests detect this change and fail. If the test passes, it means you lack test cases to catch that code change, so you should strengthen them.
- **Handle Edge Cases:** You should be prepared for unexpected input values or abnormal conditions, so your code handles them gracefully without errors or crashes.
- **Analogy:** Like inspecting a completed building to ensure it meets all building codes and safety standards.

**Step 3: Clean It Up (Polish and organize!)**

- **Core Goal:** Improve already-working and validated code to make it more readable and easier to maintain.
- **Refactor Freely:** Now we have a safety net of test code! Refactor with confidence to improve code structure and readability without worrying about breaking functionality.
- **Resolve Your To-Do List:** Address the improvements you noted in Step 1, one by one. (For example: extract duplicate code blocks into functions, rename variables more clearly, move related logic to utility files, etc.)
- **Run Tests Often:** Keep running tests during refactoring to quickly discover and fix any problems.
- **Analogy:** Like putting nice wallpaper on a safety-inspected house and arranging furniture to make it comfortable and pleasant to live in.

**Example: Implementing Login Functionality**

Let's say you need to add a new login feature to a website.

1. **Make It Work:** Write basic code where a user enters an ID and password, clicks 'login', the server checks the information, and login is processed. Just implement the successful login flow.
2. **Make It Right:** Write test code:
   - Login succeeds with correct ID/password
   - Login fails with wrong password
   - Login fails with non-existent ID
   - No ID or password entered (edge case)
3. **Clean It Up:** Review the login code that passes tests:
   - Is there duplicate database query logic? -> Extract it into a separate function.
   - Is there a variable name like `pw`? -> Change it to something clearer like `userPassword`.
   - Check if indentation and style are consistent and clean up.

## Cautions and Tips

⚠️ **Things to Watch Out For:**

1. **Don't Get Caught in Perfectionism During Step 1:**
   - If you focus too much on writing perfect and efficient code from the start, you won't make progress. Making it work is what matters!
   - Instead of perfectionism, develop the habit of keeping a to-do list of improvements.
2. **Don't Neglect Testing in Step 2:**
   - The thought "My code shouldn't have bugs" is dangerous! Tests are a safety mechanism that saves your future self.
   - Writing tests that cover various scenarios, especially edge cases, is crucial.
3. **Don't Skip Step 3:**
   - You might think "Why fix it if it works?" But unorganized code becomes technical debt, causing bigger costs (time, effort) later.
   - Clean, readable code is easier to debug and add features to.

💡 **Pro Tips:**

- **Use Automation Tools:** Using linters or code formatters helps maintain consistent code style during the Clean It Up phase.
- **Pair Programming:** Writing or reviewing code with colleagues helps catch things you might miss in Make It Right and Clean It Up phases, improving code quality.
- **Gradual Refactoring:** Rather than changing too much at once in Clean It Up, divide improvements into small units and refactor and test incrementally for safety.

## Conclusion

We've explored the 3-step approach to writing code more effectively and cleanly: "Make It Work, Make It Right, Clean It Up". While this process might feel a bit cumbersome at first, consistent practice will help you create much more robust code that's easier to maintain long-term!
