This content is organized based on cases actually experienced by many users over the past year using agent-assisted coding.

- **Security and Sensitive Information Management**
  - Careless use can leak not just security info like API Keys but even personal IDs and passwords.
  - Developers must be especially careful, ensuring that sensitive information like IDs and passwords aren't learned by LLMs through thorough preventive blocking.

- **Development and Maintenance Difficulty and Cost**
  - Using vibe coding and agent coding allows implementing new features relatively quickly.
  - However, debugging issues discovered during maintenance—so-called "vibe debugging"—can take 10x to 100x+ longer than initial development.
  - Sometimes building from scratch is more efficient than fixing existing code.
  - Proper use of agent coding, stable maintenance, and improving existing features carry much higher difficulty than simple new development.

- **Risks of Agent Automation Use**
  - Fully delegating work to agents and neglecting monitoring can result in your direct code disappearing and being replaced by LLM-generated comments and code.
  - Operating agents like a black box risks previously working features breaking.
  - Writing "no-look code" must be absolutely avoided.

- **Importance of Git-Based Version Control**
  - Working code must always be committed to maintain history.
  - This creates the foundation to quickly rollback when unexpected issues arise.

- **Illusion of Productivity**
  - Agent coding can create illusion for both developers and non-developers that "almost everything can be handled in very short time."
  - Actually, code quality, maintenance difficulty, and cost vary dramatically depending on task difficulty.

- **Model Selection and Quality Issues**
  - High-difficulty work demands models with best reasoning performance.
  - Using low-performance models to save tokens in the short term can result in poor code and higher time/cost for subsequent fixes and improvements.

- **Potential Developer Skill Degradation**
  - Delegating most development work to agents and only handling oversight yourself risks losing the development knowledge and experience accumulated over time unless you separately pursue self-learning.
  - This resembles a process where developers gradually shift from active coding roles to PM roles without developing their competencies.
