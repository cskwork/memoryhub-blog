What's the hardest part of building a RAG system? Not the LLM—the Retriever. No matter how smart your LLM, if the retrieval phase fetches wrong documents, answer quality plummets. But training retrieval models with LLM knowledge typically requires accessing internal probability values—impossible with closed APIs like GPT-4 or Claude.

**Syntriever offers a method to train retrievers using only LLM text output.**

**One-line summary:** Syntriever is a two-stage framework achieving up to 18.6% performance improvement by training retrievers with synthetic data generated by Black-box LLMs.

## Background

Retrieval Augmented Generation (RAG) is key technology overcoming LLM limitations. LLMs don't know information post-training and produce hallucinations. RAG solves this by retrieving external documents to feed the LLM.

> RAG = Retriever (search) + Generator (create). Retrieval quality determines final answer quality.

The problem is Retriever performance. Existing methods transferred LLM knowledge to retrievers: InPars generated queries with GPT-3 for training, Promptagator created domain-specific queries from few examples. But all had common limitations.

**Requiring access to LLM output probabilities.** They judge document relevance using probability values for training signals, but commercial APIs like GPT-4, Claude, and Gemini don't provide these. These are called Black-box LLMs.

## Syntriever's Core Insight

Syntriever is a framework proposed by Korean researchers (Min-Sang Kim, Seung-Jun Baek), published in NAACL 2025 Findings. The core idea is simple.

**Use the LLM-generated text itself instead of probability values as training data.**

It has two stages.

**Stage 1 Distillation** gives the LLM queries and has it generate relevant and irrelevant documents. Like a teacher asking students to "create good and bad answers to this question."

A key mechanism here is self-verification. If the LLM-generated document contains hallucination contradicting facts, reclassify it as a hard-negative rather than positive example. If it created a wrong answer, use that as a negative example.

**Stage 2 Alignment** has the LLM re-evaluate retriever results. When the LLM judges "this document is better than that one," the retriever learns that preference. Using Partial Plackett-Luce ranking, it effectively learns from just the LLM's partial preference.

The analogy: Stage 1 is creating textbooks, Stage 2 is grading and feedback.

## Technical Implementation

Syntriever's Stage 1 uses Chain-of-Thought prompting. Rather than simply asking "generate relevant documents," it has the LLM generate reasoning—why the document is relevant. This produces more logically connected synthetic data.

Training loss uses a modified Soft Nearest-Neighbor (SNN) loss function. It learns to cluster relevant documents close and irrelevant ones far apart. Clustering multiple positive examples simultaneously is more effective than contrastive learning using single positive examples.

Stage 2's Partial Plackett-Luce model learns from partial rankings, not complete ones. The LLM only needs to compare judgments on some of the top k documents. Regularization is added to prevent forgetting Stage 1 learning.

## Performance Validation

Results from BeIR benchmark testing:

| Dataset | Improvement Over Previous Best | Key Characteristic |
| --- | --- | --- |
| MSMARCO | +18.6% (nDCG@10) | Large-scale web search |
| HotpotQA | Top performance | Multi-hop reasoning required |
| SciFact | Top performance | Scientific paper verification |
| FiQA | Top performance | Finance domain specific |

Using existing retrievers like E5 as base and GPT-series LLMs to generate synthetic data showed consistent performance gains regardless of domain.

Researchers recommend using OpenAI's Batch API for large-scale synthetic data generation. Code is publicly available on GitHub for reproduction with MSMARCO, HotpotQA, FiQA, SciFact, and NFCorpus datasets.

## Practice

The process of using Syntriever directly.

**1. Prepare Environment**

First download the BeIR dataset. Clone the Syntriever repository and install dependencies.

```
git clone https://github.com/kmswin1/Syntriever
cd Syntriever
pip install -e .
```

**2. Generate Synthetic Data**

Run parse_synthetic.py in the datasets folder. This script calls the LLM API to generate synthetic documents. For large-scale generation, OpenAI Batch API is recommended.

```
cd datasets
python parse_synthetic.py msmarco
```

**3. Stage 1 Training (Distillation)**

Train the retriever with generated synthetic data. e5 refers to the base model.

```
python train_stage1.py e5 msmarco
```

**4. Retrieval and Stage 2 Preparation**

Perform retrieval with the trained model and generate LLM comparison data for results.

```
python retrieval.py e5-sft msmarco
cd stage2
python parse_comparison.py msmarco
```

**5. Stage 2 Training (Alignment)**

Perform LLM preference alignment.

```
python train_stage2.py e5-sft msmarco
```

**6. Final Evaluation**

Measure performance with BeIR benchmark.

```
python evaluate.py e5-final msmarco
```

## Best Practices and Pattern Comparison

| Method | Advantages | Cautions |
| --- | --- | --- |
| Syntriever | Black-box LLM compatible, auto-handles hallucination | LLM API call costs |
| InPars | Simple query generation | Requires probabilities, weak negatives |
| Promptagator | Domain-specialized from few examples | Needs large LLM, requires probabilities |
| Direct labeling | Quality assured | Excessive cost and time |

Syntriever requires LLM API calls cost-wise, but researchers assess it as practical given continuously falling API prices. Follow-up research shows effective synthetic data generation is possible with smaller LLMs.

## Conclusion

- Syntriever is the first framework training retrievers using only text output from Black-box LLMs like GPT-4.
- The two-stage structure (distillation + alignment) and self-verification mechanism are core, achieving up to 18.6% performance improvement on BeIR.
- Practical tip: If your RAG system's retrieval quality is unsatisfactory, try creating domain-specialized retrievers using Syntriever's approach.
