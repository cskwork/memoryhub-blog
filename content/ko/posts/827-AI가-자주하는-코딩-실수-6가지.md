**신입일수록 안 보이는 함정과 바로잡는 법**

> “기능은 잘 돌아가요. 그래서 더 위험합니다.”  
> AI가 짠 코드는 겉으론 체크·클릭 다 되는 ‘VIBE - Very Inefficient But Entertaining (아주 비효율적이지만 재미있는)’ 코드가 되기 쉽습니다. 특히 신입 개발자는 팀 패턴과 설계 의도를 못 본 채 결과만 확인하기 때문에 더 취약하죠. 아래 6가지만 잡아도 “돌아가는 코드”를 **유지보수 가능한 코드**로 바꿀 수 있습니다.

---

## TL;DR

1. **팀 패턴 무시**: 기존 폴더 구조·레이어링을 어기는 코드 생성
2. **One Source of Truth 위반**: 타입/모델을 여러 곳에 중복 정의
3. **매직 값 하드코딩**: 상태/숫자/문자열이 여기저기 박힘
4. **예외·에러 처리 부실**: 해피 패스만 통과, 콘솔 로그로 덮기, `any` 남발
5. **단일 책임 위반**: UI·비즈 로직·IO가 한 파일/함수에 뒤엉킴
6. **Shared 관리 실종**: 재사용 유틸이 여기저기 복제, 공용 모듈 부재

---

## 1) 팀/프로젝트 **패턴 무시**

- **증상**: 디렉터리 구조·레이어드 아키텍처(controllers/services/repos 등) 무시, 팀 컨벤션과 다른 네이밍/파일 배치.
- **왜 생기나**: “기능만 되면 OK”라는 AI 기본 전략. 팀 규칙을 알려주지 않으면 모릅니다.
- **해결**
  - 먼저 팀의 **CRUD 패턴·폴더 구조·코딩 컨벤션**을 정리(읽고 예시 마련).
  - AI에 **명시 프롬프트**로 강제:
  - 우리 팀 패턴:   
    - src/   
      - modules/{domain}/(controller|service|repo|types)   
      - shared/(utils|constants|hooks)   
    규칙을 100% 준수해 구현해. 파일 생성/수정 목록과 사유를 요약해서 먼저 제시해.

---

## 2) **One Source of Truth** 위반 (모델/타입 중복)

- **증상**: `Product` 타입을 화면·API·서비스마다 따로 정의. 필드 변경 시 전역 폭탄.
- **왜 생기나**: AI는 필요한 순간 **로컬 재정의**를 선호.
- **해결**
  - **단일 소스 파일**(예: `src/modules/product/types.ts`)을 정하고 **전 구간 import**.
  - PR 규칙: “타입 새로 만들면 먼저 검색해서 기존 모델 재사용 여부 확인

```
// ❌ 나쁜 예

// page A
type Product = { id: string; status: "CANCEL" | "DONE" }

// page B
type Product = { id: string; status: "CANCELLED" | "DONE" } // 미묘하게 다름

// ✅ 좋은 예

// src/modules/product/types.ts
export interface Product {
  id: string;
  status: ProductStatus;
}

export enum ProductStatus {
  CANCELLED = "CANCELLED",
  DONE = "DONE",
}

// 사용처
import { Product, ProductStatus } from "@/modules/product/types";
```

## 3) **매직 값 하드코딩** (상수/설정 분리 실패)

- **증상**: `"취소"`, `"완료"`, `7`, `30000` 같은 값이 코드 곳곳에 박힘. 오타/일관성 문제.
- **해결**
  - **`shared/constants`**에 상태·권한·에러 메시지·기간 등 **도메인 상수**를 모아두고 전역 사용.
  - **i18n/도메인 enum/Config**로 의도를 드러내기.

  ```
  // src/shared/constants/order.ts
  export const ORDER_STATUS = {
    CANCELLED: "CANCELLED",
    DONE: "DONE",
  } as const;

  // bad
  if (order.status === "완료") { ... }

  // good
  import { ORDER_STATUS } from "@/shared/constants/order";
  if (order.status === ORDER_STATUS.DONE) { ... }
  ```

---

## 4) **예외·에러 처리 부실** + `any` 남발

- **증상**: 정상 흐름만 통과, 오류는 `console.error`로 덮고 끝. 타입 막히면 `any`.
- **왜 생기나**: AI는 기본적으로 “해피 패스 최적화”.
- **해결 체크**
  - 실패 경로(네트워크/권한/타임아웃/중복 클릭) **명시 시나리오** 작성.
  - `try/catch` + 사용자 피드백(토스트/메시지) + 로깅(레벨/컨텍스트).
  - `any` 금지, `unknown`→ **좁히기**(type guard) 사용.

  ```
  async function submit(order: Order) {
    try {
      await api.orders.create(order);
      toast("주문이 완료됐어요.");
    } catch (e: unknown) {
      log.error("createOrder failed", { e, orderId: order.id });
      toast("주문 중 문제가 발생했어요. 잠시 뒤 다시 시도해주세요.");
    }
  }
  ```

## 5) **단일 책임 원칙 위반** (SRP)

- **증상**: UI 렌더 + 비즈니스 규칙 + API 호출 + 상태 관리가 한 파일/함수에 뒤엉킴.
- **해결**
  - 화면: **프레젠테이션 컴포넌트**
  - 로직: **서비스/훅/유틸** (순수 함수 지향)
  - IO: **API 클라이언트/리포지토리** 로 분리

  ```
  /product
    ProductPage.tsx       // UI
    useProduct.ts         // 화면 전용 상태/쿼리 조합
    product.service.ts    // 도메인 규칙(할인, 검증)
    product.repo.ts       // API/DB 접근
  ```

---

## 6) **Shared(공용) 모듈 관리 부재**

- **증상**: 유사한 유틸·훅·컴포넌트가 사본으로 난립. 수정 시 동시 다발 깨짐.
- **해결**
  - **공용화 기준**:
    - ①두 곳 이상에서 재사용
    - ②도메인 독립
    - ③테스트 가능
  - 위치 통일: `src/shared/{utils,components,hooks,constants}`
  - **기여 규칙**: 추가 시 문서화와 사용 예시 포함, 변경 시 브레이킹 체인지 로그 남기기

## 실전 체크리스트 (리뷰 전에 2분 점검)

| 항목 | 내가 던질 질문 | 통과 기준 |
| --- | --- | --- |
| 패턴 준수 | 팀 폴더/레이어 규칙을 100% 지켰나? | 파일 배치·네이밍 일치 |
| 단일 소스 | 타입/모델/스키마가 한 곳에만 정의됐나? | 전역 import만 존재 |
| 매직 값 | 상수·enum·i18n으로 분리됐나? | 하드코딩 0건 |
| 에러 처리 | 실패 시 사용자/로그가 명확한가? | 토스트+구조화 로깅 |
| SRP | 화면·로직·IO가 분리됐나? | 의존 방향 단방향 |
| Shared | 재사용 코드는 shared로 끌어올렸나? | 중복 util 없음 |

## AI에게 이렇게 시키세요 (프롬프트 템플릿)

```
역할: 우리 팀 규칙에 맞춘 구현 보조자
필수 규칙:
1) 아래 폴더/레이어 구조 100% 준수
2) 타입/모델은 단일 파일에서 import만 사용 (새 정의 금지)
3) 상수·상태는 shared/constants에서만 참조 (하드코딩 금지)
4) 모든 async 경로에 예외 처리 + 사용자 메시지 + 로깅 포함
5) UI/도메인로직/IO 분리(SRP) 및 의존 방향 유지
6) 재사용 함수는 shared로 승격, 사용 예시/간단 테스트 포함

작업 순서:
- (A) 변경 파일 목록/이유/대안 2가지를 표로 제시
- (B) 구현
- (C) 자체 점검 체크리스트 통과 증빙
```
