# 

처음 이 모델 스펙을 봤을 때 숫자가 두 번 눈에 들어왔습니다. 총 35B인데 실제로 돌릴 때는 3B만 깨어 있다는 설명이었죠.

며칠 전 알리바바가 공개한 Qwen3.6-35B-A3B입니다.

고가 GPU 없이도 30B급 성능을 쓰고 싶다는 개발자들의 오랜 요청에 직접 답한 모델이라고 해도 무리가 없어 보입니다.

## 한줄요약

Qwen3.6-35B-A3B는 256개 전문가 중 8개만 활성화해 3B 수준의 추론 비용으로 MMLU-Pro 85.2점, AIME 26 92.7점을 달성한 하이브리드 어텐션 MoE 모델입니다.

## 왜 이 모델이 지금 주목받나

조밀 모델(Dense)은 총 파라미터가 곧 연산 비용이었습니다. 32B 모델을 쓰려면 32B어치 VRAM과 연산을 매 토큰마다 감수해야 했죠. MoE(Mixture of Experts)는 이 고정비를 깨는 시도입니다.

전문가를 여러 개 두되, 입력마다 일부만 활성화해 "학습 용량은 크게, 실행 비용은 작게" 분리합니다.

용어 설명

|  |  |  |
| --- | --- | --- |
| Total Parameters | 모델에 저장된 전체 파라미터 수 | 35B |
| Activated Parameters | 토큰 한 개를 처리할 때 깨어 있는 파라미터 | 3B |
| Experts | 라우터가 선택할 수 있는 전문 네트워크 | 256개 |
| Routed + Shared | 토큰별 선택 전문가 + 항상 켜진 공통 전문가 | 8 + 1 |
| Context Length | 한 번에 받을 수 있는 토큰 수 | 기본 262,144, 확장 1,010,000 |

기존 Qwen3.5-35B-A3B는 2026년 2월 같은 라인으로 공개됐고, 4월 버전인 3.6은 어텐션 구조를 더 손본 것이 가장 큰 차이로 보고됩니다. 같은 A3B라는 이름을 달고도 내부 구성은 세대마다 조금씩 달라진다는 점을 기억해 두면 혼동을 줄일 수 있습니다.

## 아키텍처 한눈에 보기

> 한 줄 정의  
> Qwen3.6-35B-A3B는 Gated Attention과 DeltaNet Linear Attention을 한 모델 안에서 교차 배치한 256-전문가 MoE입니다.

핵심은 두 층으로 나뉩니다.

첫째, MoE 루팅은 토큰마다 256개 전문가 중 8개를 고르고, 모든 토큰이 공통으로 거치는 1개 공유 전문가를 더 얹습니다. 덕분에 라우팅이 실패해도 공유 전문가가 안전판 역할을 합니다.

둘째, 어텐션은 Gated Attention(Q 16, KV 2 헤드, 헤드 차원 256)과 DeltaNet 기반 Linear Attention(V 32, QK 16 헤드, 헤드 차원 128)을 혼합합니다. 전자가 긴 의존성의 정밀도를, 후자가 초장문에서의 연산 효율을 담당합니다. 40개 레이어 위에서 두 모듈이 교차되며 262K 네이티브 컨텍스트가 가능한 이유가 여기에 있습니다.

아래는 공식 모델 카드 기준의 주요 설정을 transformers로 로드하는 최소 예시입니다.

```
# 환경: Python 3.11 / transformers >= 4.50.0 / torch >= 2.4
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "Qwen/Qwen3.6-35B-A3B"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype="auto",
    device_map="auto",
)

messages = [{"role": "user", "content": "MoE 아키텍처의 장점을 세 줄로 요약해줘."}]
inputs = tokenizer.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt").to(model.device)
outputs = model.generate(inputs, max_new_tokens=256)
print(tokenizer.decode(outputs[0][inputs.shape[-1]:], skip_special_tokens=True))
```

## 실습 가이드

프로덕션이든 로컬 실험이든 추론 서버를 띄우는 절차는 비슷합니다. 세 단계로 끊어 보겠습니다.

### ① 환경 준비

우선 CUDA 12.4 이상과 vLLM 0.9+ 조합을 권장합니다.

35B MoE지만 활성 파라미터가 3B라, 24GB급 소비자 GPU에서도 4-bit 양자화 버전을 쓰면 구동이 가능합니다.

다만 전문가 전체 가중치는 VRAM이나 시스템 RAM 어딘가에는 상주해야 하므로 저장소 여유를 먼저 확인해야 합니다.

```
# vLLM 기반 OpenAI 호환 서버 기동
pip install "vllm>=0.9.0"
vllm serve Qwen/Qwen3.6-35B-A3B \
  --max-model-len 65536 \
  --enable-expert-parallel \
  --trust-remote-code
```

### ② 구현: OpenAI 호환 엔드포인트로 호출

서버가 뜨면 평소 쓰던 OpenAI SDK 패턴을 그대로 재활용할 수 있습니다. 아래는 Python 3.11 기준입니다.

```
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="dummy")
resp = client.chat.completions.create(
    model="Qwen/Qwen3.6-35B-A3B",
    messages=[
        {"role": "system", "content": "너는 간결하게 답하는 한국어 보조자야."},
        {"role": "user", "content": "Qwen3.6의 MoE 구조 특징 세 가지만 알려줘."},
    ],
    temperature=0.3,
)
print(resp.choices[0].message.content)
```

### ③ 테스트: 컨텍스트 확장과 지연 측정

네이티브 262K를 넘어 1M 토큰까지 넣어야 한다면 --rope-scaling 옵션과 YaRN 계수를 함께 지정해야 합니다. 실측 환경에서는 100K 토큰 입력 기준 지연이 vLLM + A100 80GB 조합에서 초당 150~180 토큰의 출력 속도 범위로 보고되고 있습니다(모델 카드 및 3.5 A3B 관련 리포트 기준).

간단 결과 캡처 예시(텍스트 대체):

```
> prompt_tokens: 128,  completion_tokens: 256
> first_token_latency: 0.41s
> tokens_per_second: 173.2
> answer: "MoE 구조의 핵심은 ①희소 활성화로 비용 절감, ②공유 전문가로 안정성 확보, ③하이브리드 어텐션으로 장문 확장성 유지입니다."
```

## 동급 A3B 모델 비교

같은 "A3B" 접미사를 달고 있어도 실제로는 세대마다 성격이 제법 다릅니다. 라인업을 한 표에 정리하면 선택 기준이 명확해집니다.

패턴 장점 주의점

|  |  |  |
| --- | --- | --- |
| Qwen3.6-35B-A3B (2026-04) | MMLU-Pro 85.2, AIME 26 92.7, 컨텍스트 1M까지 확장. 추론·코딩·수학 균형이 가장 고르다 | 하이브리드 어텐션이라 구버전 추론 엔진에서 호환성 이슈 발생 가능. 최신 vLLM·transformers 필수 |
| Qwen3.5-35B-A3B (2026-02) | 동일 35B/3B 라인의 직전 세대, Apache-2.0, 262K 네이티브 컨텍스트 | 3.6 대비 SWE-bench Verified(69.2→73.4) 등 코딩 지표가 낮음 |
| Qwen3-30B-A3B (2025) | 128 전문가·32K 컨텍스트로 단순해 디버깅과 자체 호스팅이 쉬움 | 장문·에이전트 벤치에서 후속 세대에 밀림, YaRN 없이는 131K까지 |
| Qwen3-Next-80B-A3B | A3B 라인 중 최대 용량, 추론 정확도 상한이 가장 높음 | 총 파라미터 80B라 저장 비용이 3.6의 두 배 이상. 양자화 배포판 필수 |

선택 기준을 정리하면, 단일 GPU에서 장문 RAG·에이전트를 돌리고 싶다면 3.6-35B-A3B가 "현시점 스윗스팟"에 가장 가깝고,

최고 성능이 목표라면 Next-80B-A3B가 합리적입니다.

## 마치며

MoE가 실험실에서 실제 워크로드로 내려와 자리 잡는 과정을 Qwen3.6-35B-A3B가 구체적인 수치로 보여주고 있습니다.

35B라는 숫자에 겁먹을 필요 없이 3B 수준의 비용으로 고급 추론·코딩을 쓸 수 있다는 점이 핵심 메시지입니다.

오픈 라이선스(Apache-2.0)까지 맞물려 있으니, 사내 추론 허브나 개인 에이전트 실험의 기본 뼈대로 진지하게 검토해볼 시점입니다.
