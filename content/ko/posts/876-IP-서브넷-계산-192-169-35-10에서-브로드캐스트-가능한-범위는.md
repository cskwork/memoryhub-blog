```
    ┌─────────────────────────────────┐
    │  192.169.35.10 (PC)            │
    │  255.255.252.0 (Subnet Mask)   │
    └────────────┬────────────────────┘
                 │
    ┌────────────▼────────────────────┐
    │   Network: 192.169.32.0        │
    │   ┌─────────────────────┐      │
    │   │ 192.169.32.1        │      │
    │   │ 192.169.32.2        │      │
    │   │     ...             │      │
    │   │ 192.169.35.10 ◄───  │      │
    │   │     ...             │      │
    │   │ 192.169.35.254      │      │
    │   └─────────────────────┘      │
    │   Broadcast: 192.169.35.255    │
    └────────────────────────────────┘
```

회사에서 네트워크 장비를 설정하다가 막막했던 경험 있으신가요? IP 주소는 알겠는데, 서브넷 마스크 255.255.252.0이 뭔지, 브로드캐스트가 어디까지 되는지 헷갈려서 구글링만 10번 했던 기억이 납니다. 특히 네트워크 관리자나 개발자라면 이 계산법을 모르면 서버 통신 설정에서 당황하게 됩니다.

이 글을 읽으면 2진수 변환과 AND 연산으로 정확한 IP 범위를 5분 만에 계산할 수 있고, 실무에서 바로 써먹을 수 있는 네트워크 설계 감각을 얻게 됩니다.

> IP 주소 192.169.35.10과 서브넷 마스크 255.255.252.0을 2진수로 AND 연산하면 네트워크 주소 192.169.32.0을 얻고, 호스트 비트를 모두 1로 채우면 브로드캐스트 주소 192.169.35.255가 나오며, 실제 사용 가능한 IP 범위는 192.169.32.1부터 192.169.35.254까지입니다.

## 배경

### 왜 서브넷 계산이 필요한가

네트워크를 효율적으로 관리하려면 IP 주소 공간을 적절히 나눠야 합니다. 하나의 큰 네트워크보다 여러 작은 네트워크(서브넷)로 분할하면 보안, 성능, 관리 측면에서 유리합니다.

| 용어 | 정의 | 역할 |
| --- | --- | --- |
| IP 주소 | 네트워크 상 장치의 고유 식별자 | 192.169.35.10 같은 형식 |
| 서브넷 마스크 | 네트워크 부분과 호스트 부분 구분 | 255.255.252.0처럼 표현 |
| 네트워크 주소 | 해당 서브넷의 시작 주소 | 장치 할당 불가, 식별용 |
| 브로드캐스트 주소 | 해당 서브넷의 끝 주소 | 전체 장치에 동시 전송 |
| 호스트 범위 | 실제 장치에 할당 가능한 IP | 네트워크+1 ~ 브로드캐스트-1 |

### 문제 상황

기존에는 "서브넷이 뭔지 몰라서 모든 PC를 같은 대역에 몰아넣었다가 브로드캐스트 폭풍이 발생"하거나, "잘못된 IP 범위 설정으로 통신 불가" 같은 문제가 발생합니다.

## 핵심

> 서브넷 마스크는 IP 주소를 네트워크 부분과 호스트 부분으로 구분하는 필터이며, AND 연산으로 네트워크 주소를, 호스트 비트를 1로 채워 브로드캐스트 주소를 구합니다.

### 계산 원리

**서브넷 마스크의 이진 구조**

- 255 = 11111111 (네트워크 비트, 고정)
- 252 = 11111100 (일부 네트워크, 일부 호스트)
- 0 = 00000000 (호스트 비트, 변동)

**AND 연산 규칙**

- 1 AND 1 = 1
- 1 AND 0 = 0
- 0 AND 0 = 0

이 원리로 IP와 서브넷 마스크를 계산하면 네트워크 주소가 나옵니다.

## 실습

### 1단계: 문제 파악

주어진 정보를 정리합니다.

- PC IP 주소: 192.169.35.10
- 서브넷 마스크: 255.255.252.0
- 목표: 브로드캐스트 가능한 IP 범위 찾기

### 2단계: 네트워크 주소 계산

핵심은 3번째 옥텟(35와 252)의 계산입니다.

**2진수 변환**

```
IP 주소 35:      0010 0011
서브넷 마스크 252: 1111 1100
```

**AND 연산 수행**

```
  0010 0011  (35)
& 1111 1100  (252)
-----------
  0010 0000  (32)
```

**결과 해석**

- 3번째 옥텟: 32
- 네트워크 주소: **192.169.32.0**

이것이 이 PC가 속한 서브넷의 시작점입니다.

### 3단계: 브로드캐스트 주소 계산

호스트 비트를 모두 1로 채웁니다.

**서브넷 마스크 252의 호스트 비트**

```
1111 1100
     ^^-- 이 2비트가 호스트 영역
```

**네트워크 주소에서 호스트 비트를 1로 변경**

```
0010 0000 (32, 네트워크 주소)
0010 0011 (35, 호스트 비트 11로 설정)
```

**4번째 옥텟 계산**

```
0000 0000 (0, 네트워크 주소)
1111 1111 (255, 모든 비트를 1로)
```

**결과**

- 브로드캐스트 주소: **192.169.35.255**

### 4단계: 사용 가능한 IP 범위 도출

네트워크 주소와 브로드캐스트 주소는 장치에 할당할 수 없으므로 제외합니다.

- 시작: 192.169.32.0 (네트워크 주소, 사용 불가)
- 첫 번째 호스트: **192.169.32.1**
- 마지막 호스트: **192.169.35.254**
- 끝: 192.169.35.255 (브로드캐스트 주소, 사용 불가)

**총 사용 가능 IP 개수**

- 계산식: 2^(호스트 비트 수) - 2
- 호스트 비트: 2비트(3번째 옥텟) + 8비트(4번째 옥텟) = 10비트
- 개수: 2^10 - 2 = 1024 - 2 = **1022개**

### 5단계: 검증

PC의 IP 주소 192.169.35.10이 계산된 범위 안에 있는지 확인합니다.

- 192.169.32.1 ≤ **192.169.35.10** ≤ 192.169.35.254 ✓

범위 내에 있으므로 이 PC는 같은 서브넷의 모든 장치와 브로드캐스트로 통신할 수 있습니다.

## 모범사례/패턴 비교

| 서브넷 마스크 | 호스트 비트 수 | 사용 가능 IP 개수 | 주의점 |
| --- | --- | --- | --- |
| 255.255.255.0 (/24) | 8비트 | 254개 | 소규모 네트워크, 계산 간단, 가장 흔함 |
| 255.255.252.0 (/22) | 10비트 | 1022개 | 중규모 네트워크, 3번째 옥텟 계산 필요 |
| 255.255.248.0 (/21) | 11비트 | 2046개 | 대규모 네트워크, 관리 복잡도 증가 |
| 255.255.255.128 (/25) | 7비트 | 126개 | 세밀한 분할, VLAN 구성에 유용 |

## 마치며

서브넷 계산은 2진수 AND 연산과 호스트 비트 조작이라는 단순한 원리로 작동합니다. 192.169.35.10/22 네트워크는 192.169.32.1부터 192.169.35.254까지 1022개의 장치를 수용하며, 브로드캐스트 주소 192.169.35.255로 전체 통신이 가능합니다. 이 계산법을 익히면 네트워크 설계 회의에서 즉석으로 IP 할당 계획을 제시할 수 있고, 장비 설정 시 통신 오류를 사전에 방지할 수 있습니다.

**실전 적용 팁**: 온라인 서브넷 계산기로 검증하되, 원리를 이해해야 비정상 상황에서도 문제를 해결할 수 있습니다. 특히 방화벽 규칙 설정 시 정확한 네트워크 범위를 알아야 보안 정책을 올바르게 적용할 수 있습니다.
