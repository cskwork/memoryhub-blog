   AI의 USB-C 표준

Claude가 갑자기 GitHub 이슈를 읽고, Slack에 메시지를 보내고, PostgreSQL을 자연어로 조작한다면? 바로 **MCP(Model Context Protocol)** 덕분입니다. 2024년 11월 Anthropic이 공개한 이 표준은 AI와 외부 세계를 연결하는 '범용 포트' 역할을 합니다. 본 글에서는 2025년 현재 가장 검증된 MCP 서버 10가지를 소개하고, 실전 도입 전략과 보안 체크리스트를 정리했습니다.

---

## 1. MCP, 왜 지금 주목받나

### 문제의 본질: N×M 통합 지옥

기존에는 각 AI 모델(N개)마다 모든 도구(M개)에 대한 별도 통합 코드를 작성해야 했습니다. 이른바 "N×M 문제"로, 모델과 도구가 늘어날수록 통합 복잡도가 기하급수적으로 증가했습니다.

### MCP의 해법: 표준화된 프로토콜

MCP는 AI 애플리케이션과 외부 데이터 소스 및 도구 간의 원활한 통합을 가능하게 하는 오픈 프로토콜입니다. Anthropic은 이를 "AI 애플리케이션을 위한 USB-C 포트"에 비유하며, USB-C가 디바이스 연결을 표준화한 것처럼 MCP는 AI 시스템이 다양한 데이터 소스와 도구에 접근하는 방식을 표준화합니다.

### 핵심 이점

|  |  |
| --- | --- |
| 표준화 | 모델과 도구 간 의사소통을 JSON-RPC 2.0 기반으로 구조화 |
| 유연성 | 어떤 LLM이나 AI 에이전트와도 결합 가능 |
| 확장성 | 서버 하나로 여러 기능을 제공하는 구성 가능한 아키텍처 |

---

## 2. 개발자 필수 MCP 서버 10선

2025년 3월 OpenAI가, 4월에는 Google DeepMind가 MCP를 공식 채택하면서 생태계가 폭발적으로 성장했습니다. Microsoft Copilot Studio도 5월 MCP 통합을 정식 출시했습니다. 아래는 현업에서 가장 많이 쓰이는 서버 목록입니다.

### ① GitHub MCP

**역할:** 저장소 관리 자동화. 이슈 읽기, PR 관리, CI/CD 워크플로 트리거, 커밋 분석 등을 터미널을 벗어나지 않고 수행

**활용 사례:**

- 주간 팀 다이제스트 봇: 특정 레포의 최근 PR·이슈·머지 내역을 요약해 매주 월요일 Slack에 자동 게시
- 대화형 프로젝트 어시스턴트: "리뷰 대기 중인 이슈는?" 같은 자연어 질문을 구조화된 GitHub 쿼리로 변환

### ② Slack MCP

**역할:** 팀 커뮤니케이션 채널을 AI 기반 협업 허브로 전환. 채널 관리, 메시징, 파일 공유 자동화

**보안 참고:** 메시지 게시 기능은 기본 비활성화. SLACK\_MCP\_ADD\_MESSAGE\_TOOL 환경 변수로 특정 채널만 화이트리스트 설정 가능

### ③ PostgreSQL MCP

**역할:** 자연어로 데이터베이스 쿼리. 스키마 검사, SQL 생성, 성능 분석 지원

**구성 예시:**

```
{
  "postgres": {
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-postgres"],
    "env": {
      "DATABASE_URL": "postgresql://user:pass@localhost/db"
    }
  }
}
```

### ④ Puppeteer MCP

**역할:** 브라우저 자동화 및 웹 스크래핑. 실시간 검색, 링크 클릭, 스크린샷 캡처, CAPTCHA 우회

### ⑤ Google Drive MCP

**역할:** 파일 접근 및 검색. 드라이브 내 문서를 AI 컨텍스트로 직접 주입

### ⑥ Brave Search MCP

**역할:** 프라이버시 중심 웹 검색. 무료 티어 월 2,000회 쿼리 제공(Google Custom Search는 일 100회)

### ⑦ Cloudflare MCP

**역할:** 엣지 네트워크 활용 저지연 AI 워크플로. DNS 레코드 관리, WAF 규칙 자동화, 1,200만 도메인 지원

### ⑧ File System MCP

**역할:** 로컬 파일/디렉토리 조작. 읽기·쓰기·삭제 등 파일 시스템 작업

### ⑨ AWS API MCP

**역할:** AWS 서비스와 자연어 상호작용. CLI 명령을 자동 생성·실행하며 IAM으로 안전한 액세스 제어

### ⑩ Context7 MCP

**역할:** 최신 문서·예제를 프롬프트에 바로 주입해 레퍼런스 컨텍스트 강화

## 3. 실전 도입: 3단계 워크플로

### ① 클라이언트 선택

Claude Desktop, VS Code, Cursor 등 MCP 호스트 역할을 하는 AI 앱 선택

### ② 서버 연결 (로컬/원격)

MCP는 로컬 실행 서버와 원격 SSE 서버 모두 지원

**Cursor 기준 설정 예시:**

```
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "<YOUR_TOKEN>" }
    },
    "postgres": {
      "command": "npx", 
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "DATABASE_URL": "postgresql://..." }
    }
  }
}
```

### ③ 조합 전략 (유스케이스별)

목적 추천 조합 효과

|  |  |  |
| --- | --- | --- |
| 코드 작업 | GitHub + Repomix + Context7 | 레포 자동화 + 코드 맥락 + 최신 레퍼런스 |
| 웹 리서치 | Jina MCP(웹 읽기·검색 파이프라인) | 정제된 웹 문서 추출 및 리랭킹 |
| 디자인↔코드 | Figma Dev Mode MCP | 디자인 사양을 코드 워크플로에 자동 반영 |

## 4. 보안: 체크리스트와 모범 사례

2025년 4월, 보안 연구자들은 프롬프트 인젝션, 도구 권한 조합을 통한 파일 유출, 유사 도구로 신뢰 서버 대체 등 다수의 취약점을 발표했습니다.

### 핵심 위협 벡터

위협 설명

|  |  |
| --- | --- |
| Line Jumping 공격 | 악성 서버가 도구 설명에 프롬프트를 삽입해 AI를 조작 |
| Confused Deputy | MCP 프록시 서버가 정적 Client ID로 동작할 때 인증 토큰 탈취 가능 |
| 세션 하이재킹 | 예측 가능한 세션 ID를 통한 비인가 접근 |
| 저장된 프롬프트 인젝션 | SQL 인젝션으로 DB에 악성 프롬프트 저장 후 에이전트 워크플로 침해 |

### 필수 보안 수칙

**1. 최소 권한·승인 플로우**

- 서버별 읽기/쓰기 범위를 최소화하고 실행 전 사용자 승인 요구
- 도구 실행 시 명시적 동의 대화 상자 표시(특히 원클릭 설치)

**2. 토큰 및 인증 강화**

- MCP 서버는 해당 서버 전용으로 발급된 토큰만 수용(Resource Indicators RFC 8707 필수)
- 외부 ID 공급자(Microsoft Entra ID 등)에 인증 위임. 2025년 4월 MCP 스펙 업데이트로 가능

**3. 입력 검증 및 샌드박스**

- OWASP Top 10, LLM 보안 기준 준수. SQL/경로 순회/프롬프트 인젝션 방어
- 로컬 MCP 서버를 샌드박스에서 실행해 접근 범위 제한

**4. 감사 로그 및 공급망 관리**

- 어떤 도구가 어떤 입출력을 남겼는지 기록. 서버 버전 고정으로 공급망 리스크 감소
- SAST(정적 분석), SCA(소프트웨어 구성 분석)로 의존성 취약점 탐지

**5. 실전 사례: MCP Inspector 취약점**

- 2025년 7월 Oligo Security 팀이 Anthropic의 MCP Inspector에서 원격 코드 실행(RCE) 취약점(CVE-2025-49596) 발견. 네트워크 설정 오류와 인증 부재로 브라우저만으로 침투 가능
- 패치(v0.14.1)는 CORS 검증, 토큰 인증, 요청 출처 확인 등 기본 보안 통제를 추가해 해결

## 5. 마치며

**핵심 3줄 요약:**

1. MCP는 2025년 AI 통합의 백본으로 자리잡았으며, 90%의 기업이 연말까지 도입할 것으로 전망됩니다
2. GitHub·Slack·Postgres 등 검증된 서버를 조합하면 개발 속도가 체감 수준으로 빨라집니다
3. 2025년 6월 스펙 업데이트(OAuth 리소스 서버 분류, Resource Indicators 의무화)로 보안이 강화되었지만, 프롬프트 인젝션 등 프로토콜 레벨 취약점은 여전히 주의 필요

**실무 적용 팁:**  
우아한형제들 사례처럼, 내부 API를 MCP 서버로 래핑하면 LLM이 자사 서비스를 직접 조작 가능. 다만 도구별 입력 검증·접근 제어·호출 제한을 반드시 구현하세요

**한 줄 인사이트:**  
지금은 "프롬프트 엔지니어링"이 아니라 "MCP 컴포저블 아키텍처"가 생산성을 가르는 시대—팀에 맞는 2~3개 서버만 잘 엮어도 워크플로가 달라집니다.
