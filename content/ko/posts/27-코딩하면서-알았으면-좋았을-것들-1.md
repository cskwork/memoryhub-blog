1. 모든 데이터가 존재하려면 **주소**와 이름 그리고 타입과 사이즈가 있어야 한다. 여기서 주소가 가장 눈으로 보기 힘들어서 어디서 어떻게 가져왔는지를 늘 염두해 둘 필요가 있다. Ctrl 누르고 해당 클래스를 클릭하면 어떻게 만들어졌는지 확인할 수 있는 경우도 있다.
2. 코드를 볼 때 **거시에서 미시**로 파라미터와 리턴값 그 다음 로직을 보기
3. 일단 처음에 무언가 만들기 전에 CRUD 중 어떤 걸 할 건지를 파악하고. 어떤 조건에서 CRUD중 하나가 발동한건지를 정하고. 그 다음엔 어떤 값을 CRUD할 건지 선택하고 매우 간단한 폼으로 정확히 전달하고자 하는 **값만 일단 전송/받기** 하는 걸 완성하자 (테이블 같은 것 전부 무시하고 input태그 만으로).
4. <input name=""> 태그가 있으면 값을 전달할 때 name이 key값이 되고 input 태그 안에 있는 값은 value 값이다. 이러한 **key, value 맵**이 때로는 또른 map이라는 키값에 저장되는 경우도 있다. (DTO를 commandMap으로 사용할 경우)
5. select 또는 update(delete 용도로) 를 할 경우에는 폼에서 받는 값은 보통 **IDX** (즉 UNIQUE KEY값)이다. 그걸 기준으로 다른 데이터를 sql로 불러오면 되니까 전체 값을 파라미터로 넘겨줄 필요가 전혀 없다.
6. insert, update는 리턴 값이 필요가 없다. DB에 적는 것 뿐이니까. 그래서 service, dao 영역에서 return은 **null**이다.
7. 설정이 매우 중요하다. 필요한 도구를 import했는지, 올바른 **URI**를 사용하고 있는지, 예를 들어 폼 URI와 실제 액션 URI를 구분했으면 그것에 맞는 URI로 요청을 해야 한다. Interceptor일 경우 원하는 경로에 추가되었는지. viewResolver는 prefix/suffix가 지정한 경로와 일치하는지 등
8. NULL인 경우 데이터 값이 실제로 입력되었는지 확인해보고 올바르게 입력되었는지도 보고 db에서도 확인하고, null데이터를 그래도 불러오는 경우 처리하는 조건을 sql에 작성하자. 데이터 타입, 사이즈, 데이터 명 전부 확인해야 한다.
9. 에러 발생시 콘솔을 제일 먼저 확인하고, 데이터를 **눈으로 확인**하고, 경로를 확인하고, 코드를 제대로 이해하고 있는지 한번 더 분석해라. (때로는 툴 문제면 clean해서 cache삭제를 해보도록)
10. 무조건 rar로 기능이 하나 구현될 때마다 **백업**하도록
11. 코드가 한번에 이해 안되면 또 다시 보고 또 보고해서 **익숙**해지고 눈으로 확인하고 반복해라.
12. 적절한 **휴식** 정말 중요하다.
13. 햇갈리고 안될 수록 더 **천천히** 속도를 늦추고 차근차근 접근하기.
