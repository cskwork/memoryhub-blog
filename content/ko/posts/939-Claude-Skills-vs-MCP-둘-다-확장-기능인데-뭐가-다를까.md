MCP 열풍이 불면서 수많은 개발자들이 Claude에 외부 도구를 연결하기 시작했습니다. 그런데 2025년 10월, Anthropic이 Skills라는 새로운 기능을 발표했습니다. "이것도 확장 기능 아닌가? MCP랑 뭐가 다르지?" 이런 의문이 드는 것은 당연합니다. 결론부터 말하면, **MCP는 Claude가 '무엇에 접근할지'를, Skills는 '어떻게 행동할지'를 정의합니다.** 둘은 경쟁 관계가 아니라 서로 다른 역할을 하는 보완 관계입니다.

**한줄요약:** MCP는 외부 시스템 연결용 프로토콜이고, Skills는 작업 수행 방법을 가르치는 마크다운 기반 지침서입니다.

---

## 배경

AI 에이전트 시대가 본격화되면서 LLM을 확장하는 방법에 대한 관심이 폭발적으로 늘었습니다. 단순히 좋은 프롬프트를 작성하는 것만으로는 부족해졌습니다. 외부 데이터베이스를 조회하고, API를 호출하고, 특정 업무 프로세스를 따르게 하려면 더 체계적인 접근이 필요합니다.

Anthropic은 이 문제를 두 가지 방향에서 해결했습니다. 2024년 11월에 발표한 MCP(Model Context Protocol)는 외부 시스템 연결을 표준화했고, 2025년 10월에 발표한 Skills는 반복적인 작업 수행 방식을 패키징하는 방법을 제시했습니다. 문제는 두 기능의 경계가 언뜻 모호해 보인다는 점입니다.

> MCP는 AI의 신경계(외부와 연결), Skills는 AI의 플레이북(행동 지침)이라고 이해하면 됩니다.

---

## MCP란 무엇인가

MCP(Model Context Protocol)는 AI 모델이 외부 시스템과 통신하는 방식을 표준화한 **오픈 프로토콜**입니다. 쉽게 말해, AI 세계의 USB-C 포트라고 생각하면 됩니다. 한 번 MCP 서버를 만들어두면 Claude Desktop, IDE 확장, 다른 AI 클라이언트에서 모두 재사용할 수 있습니다.

MCP의 핵심 구성요소는 세 가지입니다. **MCP Host**는 Claude와 같이 외부 데이터에 접근하려는 AI 애플리케이션입니다. **MCP Client**는 Host 내부에서 각 MCP 서버와 1:1 연결을 유지하는 컴포넌트입니다. **MCP Server**는 데이터베이스, API, 파일 시스템 등 외부 리소스를 표준 인터페이스로 노출하는 서버입니다.

실제 활용 예시를 보면 이해가 빠릅니다. 영업팀 AI 에이전트가 CRM 데이터베이스를 조회해야 한다면 MCP 서버를 통해 연결합니다. CI/CD 봇이 GitHub 이슈를 가져와야 한다면 GitHub MCP 서버를 활용합니다. Slack 메시지를 검색하거나 Notion 페이지를 읽어오는 것도 모두 MCP의 영역입니다.

MCP의 강점은 **표준화와 재사용성**입니다. 한 번 구축한 MCP 서버는 Claude뿐 아니라 MCP를 지원하는 모든 AI 모델에서 사용할 수 있습니다. OpenAI의 Agents SDK도 MCP 지원을 명시하고 있습니다. 다양한 언어(Python, TypeScript, Java, Kotlin)용 SDK가 제공되어 구현도 비교적 수월합니다.

다만 MCP에는 **토큰 소모 문제**가 있습니다. GitHub 공식 MCP 서버의 경우 초기 컨텍스트만으로 수만 토큰을 소비하는 것으로 알려져 있습니다. 여러 MCP를 연결할수록 실제 작업에 쓸 수 있는 컨텍스트 공간이 줄어듭니다.

---

## Skills란 무엇인가

Skills는 Claude에게 특정 작업을 수행하는 방법을 가르치는 **마크다운 기반 지침 패키지**입니다. 기술적으로는 SKILL.md 파일(YAML 프론트매터 + 마크다운 지침)과 선택적 스크립트/리소스가 담긴 폴더입니다.

Skills의 작동 방식은 단순합니다. Claude가 사용자 요청을 받으면, 등록된 Skills의 메타데이터를 스캔합니다. 관련성이 높은 Skill만 컨텍스트에 로드합니다. 필요에 따라 추가 참조 문서나 스크립트를 점진적으로 불러옵니다. 이 **점진적 로딩(Progressive Loading)** 방식 덕분에 토큰 효율이 매우 높습니다.

Skills가 빛나는 상황은 명확합니다. PDF 보고서를 특정 형식으로 생성해야 할 때, 코드 리뷰를 팀 컨벤션에 맞게 수행해야 할 때, 데이터 분석 결과를 정해진 템플릿으로 정리해야 할 때 Skills가 적합합니다. 외부 시스템 연결 없이도 작동하며, 마크다운 파일만 작성하면 되기 때문에 진입 장벽이 낮습니다.

Simon Willison(저명한 개발자/블로거)은 Skills에 대해 "MCP보다 더 큰 변화가 될 수 있다"고 평가했습니다. 그 이유는 단순함입니다. MCP는 프로토콜 스펙, 서버, 클라이언트, 전송 방식 등 이해해야 할 것이 많습니다. 반면 Skills는 문서 작성 능력만 있으면 만들 수 있습니다.

## 핵심 차이 비교

| 구분 | MCP | Skills |
| --- | --- | --- |
| **핵심 질문** | "무엇에 접근할 수 있는가?" | "어떻게 수행해야 하는가?" |
| **구현 방식** | 프로토콜 + 서버 구축 | 마크다운 파일 작성 |
| **토큰 효율** | 낮음 (수천~수만 토큰) | 높음 (필요시만 로딩) |
| **외부 연결** | 핵심 기능 | 제한적 (OAuth 미지원) |
| **학습 곡선** | 가파름 | 완만함 |
| **표준화** | 오픈 프로토콜 (벤더 중립) | Anthropic 고유 (개념은 이식 가능) |
| **적합 용도** | 실시간 외부 데이터 통합 | 반복 작업 표준화, 워크플로우 정의 |

비유로 정리하면 이렇습니다. MCP는 **배관공**입니다. 집 안에 수도관을 연결해서 물(데이터)이 흐르게 합니다. Skills는 **작업 매뉴얼**입니다. "이 상황에서는 이렇게 하라"는 지침을 제공합니다. 배관이 연결되어 있어도 매뉴얼 없이는 일관된 작업이 어렵고, 매뉴얼이 있어도 배관이 없으면 외부 데이터에 접근할 수 없습니다.

## 실전 시나리오: 고객 지원 AI 에이전트

두 기능의 관계를 가장 잘 보여주는 예시는 고객 지원 에이전트 구축입니다.

**MCP로 해결하는 것**: 티켓 시스템(Zendesk, Jira)에 접근하여 고객 문의를 조회합니다. CRM 데이터베이스에서 고객 이력을 가져옵니다. 필요시 이메일 발송 API를 호출합니다. 이것이 "외부 연결" 영역입니다.

**Skills로 해결하는 것**: 고객 응대 톤과 말투를 정의합니다. 문제 유형별 에스컬레이션 기준을 명시합니다. 답변 템플릿 형식을 지정합니다. 환불 요청 처리 시 확인해야 할 체크리스트를 제공합니다. 이것이 "행동 방식" 영역입니다.

MCP만 있으면 데이터에 접근할 수 있지만 일관된 품질을 보장하기 어렵습니다. Skills만 있으면 행동 방식은 정의되지만 실시간 고객 데이터를 활용할 수 없습니다. **두 기능을 조합할 때 진정한 AI 에이전트**가 완성됩니다.

---

## 언제 무엇을 선택할까

**MCP를 선택해야 할 때**: 실시간으로 외부 시스템 데이터가 필요한 경우입니다. GitHub 저장소 상태 조회, CRM 고객 정보 검색, Slack 채널 메시지 분석 등이 해당합니다. 또한 Claude 외 다른 AI 모델에서도 같은 통합을 재사용하려 할 때 MCP가 적합합니다.

**Skills를 선택해야 할 때**: 외부 시스템 연결 없이 특정 형식의 작업을 반복해야 할 때입니다. 일일 스탠드업 회의록을 정해진 형식으로 정리하거나, 코드를 팀 컨벤션에 맞게 리뷰하거나, 특정 템플릿으로 문서를 생성하는 작업이 여기에 해당합니다. 토큰 효율이 중요한 상황에서도 Skills가 유리합니다.

**둘 다 사용해야 할 때**: 외부 데이터 접근과 일관된 작업 품질이 모두 필요할 때입니다. 앞서 예시로 든 고객 지원 에이전트, 데이터 저널리즘 에이전트(외부 데이터 수집 + 분석 방법론), 코드 배포 자동화(GitHub/CI 연결 + 릴리즈 노트 작성 규칙) 등이 이에 해당합니다.

---

## 마치며

- MCP는 Claude가 외부 세계에 접근하는 신경계이고, Skills는 Claude가 작업을 수행하는 플레이북입니다.
- 둘은 경쟁 관계가 아니라 보완 관계이며, 복잡한 AI 에이전트일수록 두 기능을 함께 활용해야 합니다.
- Skills의 토큰 효율성과 낮은 진입 장벽은 MCP 중심의 생태계에 새로운 가능성을 열고 있습니다.

실전 팁: 오늘 당장 반복하는 작업 하나를 SKILL.md 파일로 정리해 보세요. 마크다운만 작성할 줄 알면 5분이면 첫 Skill을 만들 수 있습니다.
