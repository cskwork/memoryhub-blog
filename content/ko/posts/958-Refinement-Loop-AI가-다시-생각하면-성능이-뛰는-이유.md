이메일을 쓸 때 첫 문장을 바로 보내는 사람은 드뭅니다. 초안을 쓰고, 다시 읽어보고, 어색한 부분을 고칩니다. 프로그래머도 마찬가지입니다. 코드를 작성한 뒤 실행해보고, 오류를 발견하면 수정합니다. 그런데 우리는 AI에게는 이런 기회를 주지 않았습니다. 질문 한 번에 완벽한 답을 기대했습니다. **Refinement Loop는 AI에게 '퇴고'의 기회를 주는 기술입니다.** 그리고 이 단순한 아이디어가 2025년 AI 추론 발전의 핵심 동력이 되었습니다.

결론부터 말하면, Refinement Loop는 LLM이 자신의 출력을 스스로 평가하고 반복적으로 개선하는 방식으로, 추가 훈련 없이도 5%에서 40%까지 성능을 향상시킵니다.

## 배경

ARC Prize 팀은 2025년을 공식적으로 "Refinement Loop의 해(Year of the Refinement Loop)"로 명명했습니다. 이유가 있습니다. 올해 AI 추론 분야의 주요 돌파구는 대부분 이 기법에서 나왔습니다.

> Refinement Loop: AI가 출력물을 생성한 뒤, 같은 모델이 그 출력물을 평가하고, 피드백을 바탕으로 개선하는 과정을 반복하는 기법

기존 LLM 사용 방식은 단순했습니다. 질문을 입력하면 답이 나옵니다. 이것을 "단일 패스(single-pass)" 방식이라 부릅니다. 문제는 LLM이 첫 시도에서 최적의 답을 내놓지 못하는 경우가 많다는 것입니다. 특히 복잡한 추론, 다단계 문제, 여러 제약 조건을 동시에 만족해야 하는 과제에서 그렇습니다.

2023년 Carnegie Mellon 연구팀이 발표한 Self-Refine 논문이 이 문제에 대한 해법을 제시했습니다. 핵심 통찰은 명쾌합니다. LLM에게 자기 출력물을 다시 보여주고 "이거 어때?"라고 물으면, 스스로 문제점을 찾아냅니다. 그리고 그 피드백을 바탕으로 수정하라고 하면, 더 나은 결과를 만들어냅니다.

## Refinement Loop의 3단계 구조

Refinement Loop는 세 가지 핵심 단계로 구성됩니다.

**1단계: Generate (생성)**

LLM에게 문제를 제시하고 초기 답변을 받습니다. 이 단계는 기존 방식과 동일합니다. 중요한 차이는 이 답변을 최종 결과로 받아들이지 않는다는 점입니다.

**2단계: Feedback (피드백)**

동일한 LLM(또는 다른 LLM)에게 초기 답변을 보여주고 평가를 요청합니다. 이때 단순히 "좋다/나쁘다"가 아니라 구체적이고 실행 가능한 피드백을 요구합니다. 무엇이 문제인지, 어디를 고쳐야 하는지, 왜 그런지를 명시하도록 합니다.

**3단계: Refine (개선)**

피드백을 기반으로 답변을 수정합니다. 수정된 답변은 다시 Feedback 단계로 돌아갈 수 있습니다. 이 과정은 품질 기준을 충족하거나 최대 반복 횟수에 도달할 때까지 계속됩니다.

```
┌─────────────────────────────────────────────────────────┐
│                    REFINEMENT LOOP                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   Input ──► [GENERATE] ──► Output_0                    │
│                               │                         │
│                               ▼                         │
│                         [FEEDBACK]                      │
│                "이 코드에서 예외 처리가 누락됨"           │
│                               │                         │
│                               ▼                         │
│                          [REFINE]                       │
│                               │                         │
│                               ▼                         │
│                          Output_1                       │
│                               │                         │
│                    ┌──────────┴──────────┐             │
│                    │  품질 기준 충족?     │             │
│                    └──────────┬──────────┘             │
│                         Yes   │   No                    │
│                          ▼    │    ▼                    │
│                       [종료]  └──► [FEEDBACK]           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 왜 효과가 있는가

단순히 여러 번 시도하는 것과 Refinement Loop는 근본적으로 다릅니다. 여러 번 독립적으로 생성해서 좋은 것을 고르는 방식(sampling)은 각 시도가 이전 시도로부터 배우지 못합니다. 반면 Refinement Loop는 이전 시도의 실패에서 구체적인 개선 방향을 도출합니다.

Self-Refine 연구에서 관찰된 핵심 현상이 있습니다. 수학 추론 과제에서 초기 Python 코드의 71%가 return 문을 누락했습니다. 명시적으로 return 문을 포함하라고 지시했음에도 그랬습니다. 하지만 피드백 단계에서 LLM은 이 문제를 정확히 짚어냈고, 개선 단계에서 19%의 오류율 감소를 달성했습니다. 정확도는 22.1%에서 59.0%로 뛰었습니다.

**정보이론적 관점에서 보면, Refinement 자체가 지능입니다.** ARC Prize 팀의 표현을 빌리면, 하나의 프로그램을 다른 프로그램으로 점진적으로 변환하면서 목표에 가까워지는 과정이 바로 추론의 본질입니다.

## 실제 성능 향상 수치

Self-Refine 연구에서 7가지 다양한 과제에 대해 측정한 결과입니다.

| 과제 유형 | 초기 점수 | 3회 반복 후 | 향상률 |
| --- | --- | --- | --- |
| 코드 최적화 | 22.0 | 28.8 | +31% |
| 감정 반전 | 33.9 | 36.8 | +9% |
| 수학 추론 | 22.1% | 59.0% | +167% |
| 제약 조건 생성 | 기준 | +20% 이상 | 유의미 |

Poetiq의 사례는 더 극적입니다. ARC-AGI-2 벤치마크에서 Gemini 3 Pro의 기본 성능 31%를 Refinement Loop로 감싸서 54%까지 끌어올렸습니다. 비용도 $77에서 $31로 절감했습니다. 모델을 한 줄도 수정하지 않고 달성한 결과입니다.

## Poetiq의 구현: Self-Auditing의 추가

Poetiq는 기본 Refinement Loop에 중요한 개념을 하나 더 추가했습니다. Self-Auditing(자가 감사)입니다.

기본 Refinement Loop의 문제는 언제 멈춰야 하는지 결정하기 어렵다는 점입니다. 무한히 반복하면 비용만 늘어납니다. Poetiq의 시스템은 스스로 "충분히 좋은가?"를 판단합니다. 충분하다고 판단되면 더 이상의 반복 없이 종료합니다.

Poetiq가 제시한 두 가지 원칙을 정리하면 다음과 같습니다.

첫째, **프롬프트는 인터페이스일 뿐, 지능이 아닙니다.** 단일 질문으로 완벽한 답을 기대하는 대신, 반복적인 문제 해결 루프를 통해 답을 점진적으로 구축합니다.

둘째, **자기 감사가 비용 효율의 핵심입니다.** 시스템이 스스로 진행 상황을 모니터링하고 충분한 정보와 만족스러운 해답에 도달했는지 판단합니다.

## 구현 패턴

Refinement Loop의 기본 구조를 의사 코드로 표현하면 다음과 같습니다.

```
def refinement_loop(prompt: str, max_iterations: int = 3) -> str:
    # 1단계: 초기 출력 생성
    output = llm.generate(prompt)

    for i in range(max_iterations):
        # 2단계: 피드백 생성
        feedback = llm.generate(
            f"다음 출력을 평가하고 구체적인 개선점을 제시하세요:\n{output}"
        )

        # 종료 조건 확인
        if is_satisfactory(feedback):
            break

        # 3단계: 피드백 기반 개선
        output = llm.generate(
            f"피드백을 반영하여 출력을 개선하세요:\n"
            f"기존 출력: {output}\n"
            f"피드백: {feedback}"
        )

    return output
```

핵심은 피드백의 품질입니다. 단순히 "좋다/나쁘다"가 아니라, 무엇이 문제인지와 어떻게 고쳐야 하는지를 구체적으로 명시해야 합니다. 이것을 "실행 가능한 피드백(actionable feedback)"이라 부릅니다.

## 적용 시 주의점

| 상황 | 권장 사항 | 이유 |
| --- | --- | --- |
| 단순 사실 질문 | 단일 패스 유지 | 반복이 불필요한 오버헤드 |
| 복잡한 추론 | Refinement Loop 적용 | 성능 향상 효과 큼 |
| 검증 가능한 과제 | 적극 권장 | 피드백 품질 확보 용이 |
| 주관적 과제 | 주의 필요 | 종료 조건 설정 어려움 |

Refinement Loop가 모든 상황에 적합한 것은 아닙니다. Self-Refine 연구에 따르면, 이 기법은 기반 모델의 능력에 크게 의존합니다. GPT-4와 Self-Refine의 조합이 GPT-3.5와 Self-Refine보다 훨씬 좋은 결과를 냅니다. 또한 피드백을 검증할 수 있는 과제(코드 실행, 수학 검산 등)에서 효과가 더 뚜렷합니다.

## 마치며

- Refinement Loop는 LLM에게 "다시 생각할" 기회를 주는 기법으로, 추가 훈련 없이 5~40% 성능 향상을 가져옵니다.
- 핵심 구조는 Generate → Feedback → Refine의 반복이며, 실행 가능한 피드백이 성공의 열쇠입니다.
- ARC Prize가 2025년을 "Refinement Loop의 해"로 명명할 만큼, 현재 AI 추론 발전의 핵심 패러다임입니다.

실전 팁: 복잡한 추론이 필요한 LLM 애플리케이션이 있다면, 단일 호출을 Refinement Loop로 교체해보세요. Poetiq의 오픈소스 코드나 Self-Refine 패턴을 참고하면 빠르게 적용할 수 있습니다.
