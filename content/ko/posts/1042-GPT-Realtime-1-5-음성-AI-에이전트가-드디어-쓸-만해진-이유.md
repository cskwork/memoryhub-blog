"AI 음성 비서를 만들어봤는데, 지시사항을 절반도 못 따라가더라." 음성 에이전트를 프로덕션에 올려본 개발자라면 한 번쯤 겪어봤을 좌절이다. 음성 인식 따로, 텍스트 생성 따로, 음성 합성 따로 연결하면 지연 시간은 늘어나고,

뉘앙스는 사라진다. OpenAI가 2026년 2월 23일 공개한 gpt-realtime-1.5는

바로 이 문제의 답을 한 단계 더 끌어올린 모델이다.

**이 글을 읽으면 gpt-realtime-1.5가 이전 모델과 무엇이 다르고, 음성 에이전트 개발에 어떤 의미를 갖는지 명확하게 이해할 수 있다.**

**한줄요약:** 결론부터 말하면, gpt-realtime-1.5는 추론 능력, 영숫자 인식,

명령어 준수 성능을 각각 5~10%씩 끌어올려 음성 AI 에이전트를 프로덕션 환경에서 실제로 쓸 수 있는

수준으로 만든 모델이다.

## 배경

음성 AI는 지난 2년간 급격한 변화를 겪었다. 기존 방식은 STT(음성-텍스트 변환), LLM(텍스트 생성), TTS(텍스트-음성 변환)라는 세 단계를 각각 연결하는 파이프라인 구조였다. 문제는 이 구조에서 발생하는 지연 시간과 정보 손실이다.

사람의 웃음, 억양 변화, 언어 전환 같은 비언어적 신호가 텍스트 변환 과정에서 사라진다.

> 엔드투엔드 음성 모델이란, 음성을 입력받아 중간에 텍스트로 변환하지 않고   
> 곧바로 음성으로 응답하는 방식을 말한다.

OpenAI는 2024년 10월 Realtime API를 베타로 공개하며 이 접근을 시작했고,

2025년 8월 gpt-realtime으로 정식 출시(GA)했다. 그리고 2026년 2월 23일, 한 단계 더 발전한

gpt-realtime-1.5를 릴리스했다.

그런데 왜 "1.5"일까. gpt-realtime이 프로덕션 수준의 첫 번째 모델이었다면, 1.5는 실제 현장에서 드러난 약점들, 특히 명령어 준수, 다국어 처리, 도구 호출의 안정성을 집중적으로 개선한 버전이다.

아키텍처를 근본적으로 바꾼 것이 아니라, 실전 배포에서 가장 많이 불만이 나온 지점을 정밀하게 보강한 것으로 알려져 있다.

## gpt-realtime 모델 진화 과정

이 모델이 어디서 왔고 어디로 가는지 맥락을 잡아보자.

**gpt-4o-realtime-preview (2024년 10월)** 는 Realtime API의 첫 베타 모델이었다. WebSocket 기반으로 음성 입출력을 처리했지만, 오디오 출력 토큰 가격이 100만 토큰당 200달러에 달해 실제 서비스에 적용하기 부담스러웠다. 명령어 준수나 도구 호출 정확도도 프로덕션 수준에 미치지 못했다.

**gpt-realtime (2025년 8월)** 은 정식 출시와 함께 가격을 대폭 낮추고 성능을 끌어올렸다. Big Bench Audio 추론 벤치마크에서 82.8%를 기록하며 이전 모델(65.6%) 대비 17.2%포인트 상승했다.

MultiChallenge 명령어 준수 점수는 20.6%에서 30.5%로, ComplexFuncBench 도구 호출 정확도는 49.7%에서 66.5%로 올랐다.

SIP 전화 연결, 이미지 입력, MCP 서버 지원 같은 기능도 추가되었다.

**gpt-realtime-1.5 (2026년 2월 23일)** 는 여기서 다시 한 번 세 가지 핵심 지표를 개선했다.

| 벤치마크 | gpt-realtime (2025.8) 대비 개선폭 | 의미 |
| --- | --- | --- |
| Big Bench Audio (추론) | +5% | 복잡한 질문에 대한 음성 기반 추론 향상 |
| 영숫자 인식 정확도 | +10.23% | 전화번호, 차대번호 등 정확한 인식 |
| 명령어 준수 | +7% | 개발자가 설정한 시스템 프롬프트 준수 향상 |

숫자만 보면 "겨우 5~10%?"라고 느낄 수 있다. 하지만 이 수치들이 중요한 이유가 있다. 음성 에이전트에서 영숫자 인식 오류 10%는 고객이 불러준 전화번호 10개 중 1개를 틀리게 적는 것을 의미한다.

명령어 준수 7% 개선은 "면책 조항을 반드시 읽어주세요"라는 지시를 무시하던 빈도가 의미 있게 줄었다는 뜻이다.

실제 사용 기업들의 반응이 이를 뒷받침한다. Genspark은 전화 연결 성공률이 약 66%까지 거의 두 배로 증가했고,

통화 오류가 절반으로 줄었다고 보고했다. Sendbird는 사용자가 말을 끊었을 때의 인터럽트 처리가 크게 나아졌다고 밝혔다.

## 핵심 기능과 사양

gpt-realtime-1.5의 기술적 사양을 정리하면 다음과 같다.

**입력 모달리티:** 텍스트, 오디오, 이미지. 이미지 입력은 gpt-realtime(2025.8)부터 지원된 기능으로, 고객이 제품 사진을 보내며 "이거 뭐야?"라고 물으면 음성으로 답할 수 있다.

**출력 모달리티:** 텍스트, 오디오. 텍스트 전용 모드도 가능하지만, 텍스트와 오디오를 동시에 출력하는 것은 지원하지 않는다.

**컨텍스트 윈도우:** 32,000 토큰. 최대 출력 토큰은 4,096. GPT-5 계열의 27만 토큰 컨텍스트에 비하면 작지만, 실시간 음성 대화에서 이 정도면 일반적인 고객 상담 세션을 충분히 커버한다.

**지식 컷오프:** 2024년 9월 30일. 이 부분은 gpt-realtime과 동일하며, GPT-5의 컷오프보다 1년 정도 이전이다.

**연결 방식:** WebRTC, WebSocket, SIP 세 가지를 모두 지원한다. SIP 지원은 기업 전화 시스템과의 직접 연동을 가능하게 하는 핵심 기능이다. 기존 콜센터 인프라에 AI 음성 에이전트를 바로 연결할 수 있다는 뜻이다.

**음성 옵션:** Alloy, Ash, Ballad, Coral, Echo, Sage, Shimmer, Verse 등 기존 8개 음성에 더해,

Cedar와 Marin이라는 2개의 새로운 음성을 지원한다. Cedar와 Marin은 Realtime API 전용이다. 커스텀 보이스 ID도 사용할 수 있다.

**비동기 도구 호출:** 오래 걸리는 함수 호출이 대화 흐름을 끊지 않는다. 예를 들어 예약 시스템 조회에 3초가 걸려도, 모델은 "잠시만요, 확인해볼게요"라고 말하며 자연스럽게 대화를 이어간다.

이 기능은 gpt-realtime부터 기본 내장되어 별도 코드 수정이 필요 없다.

**Semantic VAD(음성 활동 감지):** 기존의 단순 무음 감지 대신, 의미 기반으로 사용자의 발화 종료를 판단한다.

사용자가 잠깐 생각하기 위해 멈춘 것과 발화를 마친 것을 구분하여 불필요한 끼어들기를 줄인다.

## 가격 정책

가격은 기존 gpt-realtime과 동일하게 유지되었다. 같은 가격에 더 나은 성능을 제공하는 구조다.

| 토큰 유형 | 입력 (100만 토큰당) | 캐시 입력 | 출력 (100만 토큰당) |
| --- | --- | --- | --- |
| 텍스트 | $4.00 | $0.40 | $16.00 |
| 오디오 | $32.00 | $0.40 | $64.00 |
| 이미지 | $5.00 | $0.50 | - |

참고로 2024년 10월 베타 시절 오디오 출력이 100만 토큰당 200달러였던 것에 비하면,

현재 64달러는 68% 저렴해진 수준이다. 프롬프트 캐싱을 적극 활용하면 반복되는

시스템 프롬프트 비용을 대폭 절감할 수 있다.

비용 최적화를 위한 실질적인 팁이 있다. Realtime API는 대화 컨텍스트에 대한 세밀한 토큰 제한 설정과 다중 턴 일괄 잘라내기(truncation)를 지원한다. 긴 세션에서 불필요하게 누적되는 컨텍스트를 정리하면 비용을 상당히 줄일 수 있다.

## 실습: Realtime API 연결 기초

gpt-realtime-1.5를 사용하려면 Realtime API를 통해 연결해야 한다.

가장 간단한 WebSocket 연결 흐름을 단계별로 살펴보자.

1. **세션 생성**
   - Realtime API 엔드포인트(`/v1/realtime`)에 WebSocket 연결을 수립한다
   - 세션 설정에서 모델을 `gpt-realtime-1.5`로 지정한다
   - 응답 모달리티(audio 또는 text), 음성, VAD 설정 등을 구성한다
2. **시스템 프롬프트 구성**
   - `session.update` 이벤트로 시스템 메시지를 전달한다
   - gpt-realtime-1.5는 세밀한 지시사항에 더 잘 반응한다. "inaudible" 대신 "unintelligible"로 표현을 바꾸는 것만으로 노이즈 처리가 개선되는 수준이다
   - 조건문 형태(`IF x > 3 THEN ESCALATE`)보다 자연어(`3회 이상 실패하면 상담원에게 연결`)가 더 효과적이다
3. **오디오 스트리밍**
   - 클라이언트에서 오디오 청크를 실시간으로 전송한다
   - 서버가 Semantic VAD 또는 Server VAD로 발화 종료를 감지한다
   - 모델이 오디오 응답을 스트리밍으로 반환한다
4. **도구 호출 처리**
   - 모델이 함수 호출이 필요하다고 판단하면 `mcp_tool_use` 또는 function call 이벤트를 발생시킨다
   - 비동기로 동작하므로, 도구 결과를 기다리는 동안 대화가 계속된다
   - 결과가 돌아오면 모델이 이를 반영하여 응답한다

```
// 세션 설정 예시 (JavaScript)
const session = {
  model: "gpt-realtime-1.5",
  modalities: ["audio"],
  voice: "cedar",
  turn_detection: {
    type: "semantic_vad",
    eagerness: "medium"
  },
  tools: [
    {
      type: "function",
      name: "lookup_order",
      description: "주문번호로 주문 상태를 조회합니다",
      parameters: {
        type: "object",
        properties: {
          order_id: { type: "string" }
        },
        required: ["order_id"]
      }
    }
  ]
};
```

WebRTC 연결은 브라우저 기반 애플리케이션에, SIP 연결은 기존 전화 인프라 연동에 각각 적합하다.

용도에 맞는 연결 방식을 선택하면 된다.

## 모범사례/패턴 비교

음성 에이전트 구축 시 고려할 접근법을 비교한다.

| 패턴 | 장점 | 주의점 |
| --- | --- | --- |
| gpt-realtime-1.5 단독 사용 | 최저 지연 시간, 비언어적 신호 보존, 다국어 자연 전환 | 32K 컨텍스트 제한, 지식 컷오프가 2024년 9월 |
| STT + LLM + TTS 파이프라인 | 각 단계별 모델 선택 자유, 텍스트 중간 처리 가능 | 지연 시간 증가, 감정/뉘앙스 손실, 통합 복잡도 높음 |
| gpt-realtime-mini 사용 | 비용 절감, 낮은 지연 시간 | 추론 능력과 명령어 준수 정확도가 풀사이즈 모델보다 낮음 |
| 하이브리드 (간단한 건 mini, 복잡한 건 1.5) | 비용 최적화와 품질의 균형 | 라우팅 로직 필요, 모델 전환 시 세션 관리 복잡 |

gpt-realtime-1.5가 가장 적합한 시나리오는 고객 상담, 전화 기반 서비스, 다국어 지원이 필요한 음성 에이전트다.

반면, 단순 안내 방송이나 비용에 민감한 대량 호출 서비스라면 mini 모델이 더 합리적일 수 있다.

## 마치며

- gpt-realtime-1.5는 추론(+5%), 영숫자 인식(+10.23%), 명령어 준수(+7%)를 개선하여 음성 에이전트의 프로덕션 안정성을 한 단계 끌어올린 모델이다
- 가격은 gpt-realtime과 동일하게 유지되어, 기존 사용자는 모델명만 변경하면 즉시 성능 향상을 체감할 수 있다
- SIP, WebRTC, MCP 서버 연동까지 지원하므로 기업 전화 시스템부터 웹 기반 서비스까지 폭넓게 적용 가능하다
- 실전 팁: 기존에 gpt-realtime을 사용 중이라면, 세션 설정의 model 파라미터를 `gpt-realtime-1.5`로 변경하고 Semantic VAD를 활성화해보세요.
