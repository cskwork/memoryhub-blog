## 1. 배경 - 왜 지금 Rust인가?

### ? 기존 언어들의 문제점

| 언어 | 장점 | 치명적 단점 |
| --- | --- | --- |
| C/C++ | 빠른 성능 | 메모리 버그 (70% 보안 취약점) |
| Java/C# | 메모리 안전 | GC로 인한 성능 저하 |
| Python | 쉬운 문법 | 느린 실행 속도 |
| **Rust** | **모든 장점** | **러닝커브** (해결 가능!) |

### ✅ Rust가 해결하는 것들

- **메모리 안전성**: 컴파일 타임에 모든 메모리 오류 차단
- **동시성**: 데이터 레이스 원천 봉쇄
- **성능**: Zero-cost abstractions (추상화 비용 제로)

## 2. 핵심 개념 - 소유권(Ownership) 시스템

> **한 줄 정의**  
> **"모든 값은 단 하나의 주인(owner)만 가질 수 있다"** - Rust의 황금률

### 소유권 3대 규칙

1. 각 값은 owner라 불리는 변수를 가진다
2. 한 번에 하나의 owner만 존재할 수 있다
3. Owner가 스코프를 벗어나면 값은 drop된다

```
fn main() {
    // s1이 String의 owner
    let s1 = String::from("hello");

    // 소유권이 s2로 이동 (move)
    let s2 = s1;

    // println!("{}", s1); // 에러! s1은 더 이상 유효하지 않음
    println!("{}", s2); // OK: "hello"
}
```

### 빌림(Borrowing) - 소유권 없이 사용하기

```
fn main() {
    let s = String::from("hello");

    // &를 사용해 빌림
    let len = calculate_length(&s);

    println!("'{}'의 길이는 {}입니다", s, len); // s 여전히 사용 가능!
}

fn calculate_length(s: &String) -> usize {
    s.len() // 소유권 없이 값 사용
}
```

### ② 구현 - 간단한 Todo 앱

```
// main.rs
use std::io;

#[derive(Debug)]
struct Todo {
    id: u32,
    task: String,
    completed: bool,
}

impl Todo {
    // 새 Todo 생성
    fn new(id: u32, task: String) -> Self {
        Todo {
            id,
            task,
            completed: false,
        }
    }

    // 완료 표시
    fn complete(&mut self) {
        self.completed = true;
    }
}

fn main() {
    let mut todos: Vec<Todo> = Vec::new();
    let mut id_counter = 1;

    loop {
        println!("\n=== Todo 앱 ===");
        println!("1. 할 일 추가");
        println!("2. 목록 보기");
        println!("3. 완료 처리");
        println!("4. 종료");

        let mut choice = String::new();
        io::stdin().read_line(&mut choice).expect("입력 실패");

        match choice.trim() {
            "1" => {
                println!("할 일을 입력하세요:");
                let mut task = String::new();
                io::stdin().read_line(&mut task).expect("입력 실패");

                todos.push(Todo::new(id_counter, task.trim().to_string()));
                id_counter += 1;
                println!("✅ 추가 완료!");
            }
            "2" => {
                println!("\n? Todo 목록:");
                for todo in &todos {
                    let status = if todo.completed { "✓" } else { "○" };
                    println!("{} [{}] {}", status, todo.id, todo.task);
                }
            }
            "3" => {
                println!("완료할 항목 번호:");
                let mut id_str = String::new();
                io::stdin().read_line(&mut id_str).expect("입력 실패");

                if let Ok(id) = id_str.trim().parse::<u32>() {
                    if let Some(todo) = todos.iter_mut().find(|t| t.id == id) {
                        todo.complete();
                        println!("✅ 완료 처리!");
                    }
                }
            }
            "4" => {
                println!("? 안녕히 가세요!");
                break;
            }
            _ => println!("❌ 잘못된 선택입니다"),
        }
    }
}
```

## 4. 모범 사례 & 베스트 프랙티스

| 패턴 | 장점 | 주의점 |
| --- | --- | --- |
| **Result<T, E> 사용** | 명시적 에러 처리 | unwrap() 남용 금지 |
| **Iterator 활용** | 함수형 프로그래밍 스타일 | 가독성 vs 성능 균형 |
| **Trait 구현** | 다형성 & 코드 재사용 | 과도한 추상화 주의 |
| **생명주기 명시** | 컴파일 타임 안전성 | 복잡도 증가 |

### ? 실전 팁

```
// ❌ 나쁜 예
let data = get_data().unwrap(); // 패닉 위험!

// ✅ 좋은 예
let data = match get_data() {
    Ok(d) => d,
    Err(e) => {
        eprintln!("에러 발생: {}", e);
        return;
    }
};

// ✅ 더 좋은 예 (? 연산자)
let data = get_data()?;
```
