> 노트북(Notebook)처럼 단계별로 생각·코드·중간결과를 남기며 문제를 푸는 MCP 워크플로우 — 디버깅은 쉬워지고, 재현성은 올라갑니다.

---

## TL;DR

- **리터러트 리저닝**: 에이전트가 주피터 스타일 노트북을 따라 **생각→실행→검증** 과정을 기록/표현하는 MCP 패턴. 투명성·재현성이 핵심 가치.
- **왜 MCP에서 중요?** MCP는 “AI의 USB-C”처럼 다양한 도구·데이터를 표준 방식으로 연결합니다. 그 위에 **노트북 프리셋**을 얹으면, 초보자 가이드부터 고급 에이전트 행위 제어까지 깔끔하게 구조화됩니다.
- **빠른 시작**: mcp-ui로 서버가 **UI 리소스**(노트/코드 셀 뷰)를 만들어 호스트가 렌더링 → 버튼 클릭이 MCP **툴 호출**로 이어지는 인터랙티브 워크플로우 구성.

## 1) 리터러트 리저닝 한 눈에 보기

**문제**: 에이전트에게 복잡한 일을 시키면 **결과만** 떨어지고, **어떻게** 거기에 도달했는지 알기 어렵습니다(블랙박스).  
**해결**: 노트북 도구를 사용해 **지시·코드·커맨드·중간결과**를 **셀 단위**로 남깁니다. 그러면

- **투명성**: 어디서 논리/데이터가 어긋났는지 **셀 추적**으로 즉시 확인.
- **재현성**: 동일 셀 시퀀스를 재실행·분기 실행해 **같은 결과**를 재현하거나 변형 실험이 쉬움.

---

## 2) 기존 방식 vs 노트북 패턴

항목 기존 “프롬프트→답” 리터러트 리저닝(노트북)

|  |  |  |
| --- | --- | --- |
| 가시성 | 최종 답만 확인 | **셀별 추적**(지시/코드/결과) |
| 디버깅 | 재현 어려움 | **재실행/분기**로 원인 파악 용이 |
| 온보딩 | 문서 따로 필요 | **노트가 곧 튜토리얼** |
| 거버넌스 | 변경 이력 희박 | **작업 이력/감사 로그**로 관리 |

---

## 3) 핵심 구성요소

### 3-1. 마크다운 셀

- 작업 맥락/목표/체크리스트/해설을 **사람이 읽기 좋게** 기술.
- 예: “1) 새 브랜치 생성 → 2) 테스트 → 3) PR 작성” 템플릿.

### 3-2. 코드 셀

- MCP 서버가 실행할 **명령/코드**(예: git checkout -b feature-x)를 포함.
- 실행 결과/로그가 바로 아래에 남아 **검증** 가능.

### 3-3. **노트북 프리셋(Notebook Presets)**

- **미리 만들어 둔 레시피**(마크다운+코드 셀 묶음).
- 초보자 가이드, 반자동 워크플로우, 데모에 유용. 스크롤 끝의 템플릿 언급.

---

## 4) 구현 가이드 (MCP + mcp-ui 예제)

### 4-1. 전체 흐름(아키텍처)

```
[사용자/호스트] ⇄ [MCP 클라이언트] ⇄ [MCP 서버] —(UIResource)—> [호스트가 노트북 UI 렌더]
                                               └—(tool 실행/결과)—> 기록 업데이트
```

- MCP는 LLM 앱과 도구·데이터를 **표준 인터페이스**로 연결.
- mcp-ui는 서버가 보낸 **UI 리소스**를 클라이언트에서 안전하게 렌더.

### 4-2. 서버에서 UI 리소스 생성(예: 노트북 셀 뷰)

```
// TypeScript (서버) — UI 리소스 만들기
import { createUIResource } from '@mcp-ui/server';

const htmlResource = createUIResource({
  uri: 'ui://notebook/cell-1',
  content: { type: 'rawHtml', htmlString: `
    <section>
      <h3>Step 1: 문제정의</h3>
      <p>목표와 제약을 정리하세요.</p>
      <button id="go">다음 셀 실행</button>
      <script>
        document.getElementById('go').addEventListener('click', () => {
          // 버튼 클릭 → 호스트가 특정 MCP tool 호출하도록 신호
          window.parent.postMessage({ type: 'tool', payload: { toolName: 'runNextCell' } }, '*');
        });
      </script>
    </section>
  `},
  encoding: 'text',
});
```

- 포인트: uri, content, onUIAction(클라이언트 측 처리)로 **버튼→툴 호출**을 연결.

### 4-3. 클라이언트에서 렌더링

```
// React (클라이언트/호스트)
import { UIResourceRenderer } from '@mcp-ui/client';

<UIResourceRenderer
  resource={htmlResource.resource}
  onUIAction={(evt) => {
    if (evt.type === 'tool' && evt.payload.toolName === 'runNextCell') {
      // 여기에 MCP tool 실행 로직 연결
    }
  }}
/>
```

- 동일 리소스를 **웹 컴포넌트**로도 렌더 가능.

### 4-4. 노트북 툴 설계 팁

- append\_markdown\_cell(content), run\_code\_cell(code, runtime), save\_checkpoint()처럼 **의도가 분명한 툴**로 쪼개기.
- 각 툴의 응답에 **UIResource**를 포함시켜, 실행 결과가 바로 다음 셀/패널로 시각화되게.

## 5) 고급 시나리오 3가지

1. **가이드 워크플로우**: “기본 SQL 쿼리” 튜토리얼처럼 셀을 따라가면 과제를 해결.
2. **구조화된 에이전트 행위**: “노트북 X를 순서대로 수행하라” 지시로 **분해→실행→보고** 루틴을 강제.
3. **인터랙티브 데모 & 프리셋**: 파라미터만 바꿔 재실행하며 즉시 비교 실험. 마지막에 **일반 템플릿** 예시가 소개됩니다.

> 추가 아이디어: **mcp-ui**로 채팅 화면 안에 **반응형 제어판**(버튼/폼) 제공, **동적 툴 합성**, **진단 트레이스**(append-only 로그)처럼 확장 가능.

## 6) 운영 팁 & 체크리스트

### 운영 팁

- **버전 관리**: 노트북 프리셋은 Git으로 버전 태깅(태스크별 체크포인트).
- **보안/샌드박스**: 외부 URL(embed)과 원격 DOM은 **허용 타입/도메인 제한**으로 안전하게.
- **거버넌스**: 셀 실행 로그를 **감사 추적**으로 보관(누가/언제/무엇을).
- **플랫폼 호환**: MCP는 다양한 호스트/클라이언트·OS로 확장 중(예: 일부 플랫폼의 MCP 지원 발표). 보안 가드레일과 권한 설계를 함께 고려.

### 체크리스트

- 목표/제약을 **1번 셀에서 명시**
- 모든 실행 툴에 **입력·출력 스키마**(검증 포함)
- **실행 로그/아티팩트**를 셀 아래에 자동 첨부
- **재실행 전략**(전체/구간/분기) 버튼 제공
- **오류 복구 루틴**(롤백·재시도·대안 경로) 포함
- **보안 정책**(허용 MIME/도메인/툴 권한) 점검
