"오픈소스 모델은 클로즈드 모델을 절대 못 따라간다." 불과 1년 전까지만 해도 이 말은 상식처럼 통했습니다.  
그런데 2026년 2월 11일, 중국 AI 스타트업 즈푸AI(Zhipu AI, Z.ai)가 공개한 GLM-5는 이 상식에 정면으로 도전합니다. SWE-bench 코딩 벤치마크에서 Claude Opus 4.5와 3.1%p 차이,  
에이전트 벤치마크 BrowseComp에서는 오히려 25%p 앞서는 결과를 보여줬기 때문입니다.  
**오픈소스 744B 파라미터 모델이 프론티어 모델과의 격차를 사실상 해소한 사건, 그 기술적 배경과 의미를 파헤칩니다.**  

**한줄요약:** 결론부터 말하면, GLM-5는 DeepSeek의 희소 어텐션과 자체 개발 비동기 강화학습 프레임워크 Slime을 결합해,  
오픈소스 최초로 프론티어 모델급 에이전트 성능을 달성한 모델입니다.

---

## 배경

AI 모델의 세대 교체 속도가 빨라지고 있습니다. 2025년 7월 GLM-4.5가 355B 파라미터로 "에이전트 네이티브" 모델의 가능성을 보여줬고, 2026년 1월에는 즈푸AI가 홍콩 증시에 상장하며 약 435억 홍콩달러(약 7,400억 원)를 조달했습니다.  
이 자금은 GLM-5 개발에 직접 투입됐습니다.  
그런데 왜 GLM-5가 주목받는 걸까요? 단순히 파라미터 수가 커졌기 때문이 아닙니다. 핵심은 세 가지입니다.  
첫째, DeepSeek이 발명한 희소 어텐션(DSA) 기술을 흡수해 배포 비용을 대폭 낮췄습니다.  
둘째, 자체 개발한 비동기 강화학습 인프라 Slime으로 후훈련 효율을 혁신했습니다.   
셋째, MIT 라이선스로 완전 오픈소스 공개해 누구나 상업적으로 사용할 수 있습니다.

> 한 줄 정의: GLM-5는 744B 총 파라미터 중 40B만 활성화하는 MoE(Mixture of Experts) 구조의 오픈소스 대규모 언어모델로, 복잡한 시스템 엔지니어링과 장기 에이전트 작업에 특화되어 설계됐습니다.

---

## GLM-4.5에서 GLM-5로: 무엇이 달라졌나

GLM-5의 발전을 이해하려면, 전작과의 차이를 구체적으로 살펴봐야 합니다.

|  |  |  |  |
| --- | --- | --- | --- |
| 총 파라미터 | 355B | 744B | 약 2.1배 증가 |
| 활성 파라미터 | 32B | 40B | 25% 증가 |
| 사전학습 데이터 | 23T 토큰 | 28.5T 토큰 | 24% 증가 |
| 히든 레이어 | 비공개 | 78개 | - |
| 전문가 모듈 | 비공개 | 256개 (8개 동시 활성) | - |
| 최대 컨텍스트 | 128K | 202K 토큰 | 58% 확대 |
| 어텐션 메커니즘 | 기본 | DeepSeek Sparse Attention 적용 | 신규 |

파라미터가 2배 넘게 늘었지만, 실제로 추론 시 활성화되는 파라미터는 40B에 불과합니다. 이것이 MoE 아키텍처의 핵심입니다.  
전체 직원이 744명인 회사에서, 하나의 프로젝트에는 40명만 투입하는 것과 같습니다. 나머지 704명은 대기하다가 자기 전문 분야의 질문이 들어올 때만 활성화됩니다. **덕분에 모델의 "지식 용량"은 크게 늘었지만, 실행 비용은 비교적 낮게 유지됩니다.**

---

## 핵심 기술 1: DeepSeek Sparse Attention (DSA)

GLM-5가 202K 토큰이라는 긴 컨텍스트를 효율적으로 처리할 수 있는 비결은 DeepSeek이 개발한 희소 어텐션(Sparse Attention) 기술에 있습니다.  
기존의 밀집 어텐션(Dense Attention)은 입력된 모든 토큰이 다른 모든 토큰과 관계를 계산합니다.  
문서가 길어질수록 계산량이 기하급수적으로 증가하는 구조입니다. 10만 토큰짜리 문서를 처리할 때, 100억 번의 관계 계산이 필요한 셈입니다.  
DSA는 이 문제를 "선택적 집중"으로 해결합니다. Lightning Indexer라는 경량 모듈이 먼저 각 토큰의 중요도를 빠르게 평가한 뒤,  
쿼리 토큰당 2,048개의 핵심 토큰만 선별해서 어텐션을 수행합니다.  
마치 10만 쪽짜리 책을 읽을 때, 목차와 색인을 먼저 훑어보고 관련 있는 페이지만 정독하는 것과 같습니다.  
**DeepSeek-V3.2 실험에서 이 방식은 출력 품질을 거의 동일하게 유지하면서 추론 비용을 크게 절감하는 것으로 입증됐습니다.**

---

## 핵심 기술 2: Slime - 비동기 강화학습 인프라

사전학습이 모델에게 "지식"을 가르치는 단계라면, 후훈련(Post-training)은 그 지식을 "실전에서 쓸 수 있는 능력"으로 바꾸는 단계입니다. GLM-5의 후훈련 핵심은 즈푸AI가 자체 개발하고 오픈소스로 공개한 강화학습 프레임워크 **Slime**입니다.  
기존 강화학습의 가장 큰 병목은 "데이터 생성"과 "학습"이 순차적으로 진행된다는 점이었습니다.  
모델이 코드를 작성하고, 실행하고, 결과를 받아오는 데 수 분이 걸리는 에이전트 작업에서는 GPU가 대부분의 시간을 "대기"하며 낭비했습니다.  

Slime은 이 문제를 세 가지 방식으로 해결합니다.  

첫째, **비동기 분리 아키텍처**입니다. 데이터 생성(rollout)과 학습(training)을 별도 하드웨어에서 독립적으로 실행합니다. 학습 GPU는 쉬지 않고 돌아가고, 데이터 생성은 별도 서버에서 병렬로 진행됩니다.  

둘째, **혼합 정밀도 가속**입니다. 데이터 생성에는 효율적인 FP8 포맷을 쓰고, 학습에는 안정적인 BF16 포맷을 유지합니다. 데이터 생성 속도를 극적으로 높이면서도 학습 품질은 보존합니다.  

셋째, **에이전트 지향 설계**입니다. 코딩, 웹 브라우징, 도구 호출 같은 장기 에이전트 작업에서 발생하는 긴 꼬리 지연(long-tail latency)을 처리하도록 최적화되어 있습니다.  
Slime은 GLM 시리즈 외에도 Qwen3, DeepSeek V3 등 다른 모델의 학습에도 사용할 수 있도록 GitHub에 공개되어 있습니다.

## 벤치마크: 숫자로 보는 GLM-5의 실력

벤치마크 수치만으로 모델의 가치를 판단하긴 어렵지만, 경쟁 모델과의 상대적 위치를 파악하는 데는 유용합니다.

### 추론(Reasoning) 영역

|  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- |
| HLE (텍스트) | 30.5 | 25.1 | 31.5 | 28.4 | 37.2 |
| HLE (도구 사용) | 50.4 | 40.8 | 51.8 | 43.4 | 45.8 |
| AIME 2026 I | 92.7 | 92.7 | 92.5 | 93.3 | 90.6 |
| GPQA-Diamond | 86.0 | 82.4 | 87.6 | 87.0 | 91.9 |

수학 경시대회 수준의 AIME 2026에서 92.7%를 기록하며 Claude Opus 4.5(93.3%)와 0.6%p 차이를 보입니다.  
Humanity's Last Exam에서 도구를 활용할 경우 50.4%로, Claude Opus(43.4%)를 오히려 앞서는 결과입니다.

### 코딩(Coding) 영역

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| SWE-bench Verified | 77.8 | 73.1 | 80.9 | 80.0 |
| SWE-bench Multilingual | 73.3 | 70.2 | 77.5 | 72.0 |
| Terminal-Bench 2.0 | 56.2 | 39.3 | 59.3 | 54.0 |
| CyberGym | 43.2 | 17.3 | 50.6 | - |

실제 GitHub 이슈를 해결하는 SWE-bench에서 77.8%를 달성했습니다. Claude Opus 4.5(80.9%)와의 격차가 3.1%p까지 좁혀졌습니다. **이전 세대 GLM-4.7이 73.8%였으니, 한 세대 만에 4%p 향상된 셈입니다.**  
특히 다국어 코딩(73.3%)에서는 GPT-5.2(72.0%)를 앞섰습니다.

### 에이전트(Agent) 영역 - GLM-5의 진짜 강점

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| BrowseComp | 62.0 | 51.4 | 37.0 | 37.8 |
| BrowseComp (컨텍스트 관리) | 75.9 | 67.6 | 67.8 | 59.2 |
| tau2-Bench | 89.7 | 85.3 | 91.6 | 90.7 |
| MCP-Atlas | 67.8 | 62.2 | 65.2 | 66.6 |
| Vending Bench 2 | $4,432 | $1,034 | $4,967 | $5,478 |

에이전트 영역이 GLM-5의 진짜 하이라이트입니다. 웹 검색과 정보 이해를 측정하는 BrowseComp에서 62.0%로 오픈소스 1위를 기록했습니다. Claude Opus(37.0%)보다 25%p나 앞섭니다.  
MCP-Atlas(대규모 도구 호출 벤치마크)에서도 67.8%로 Claude Opus(65.2%)를 넘었습니다.  
특히 흥미로운 것은 Vending Bench 2입니다. 이 벤치마크는 모델이 1년간 가상 자판기 사업을 운영하는 시뮬레이션인데,  
GLM-5는 최종 잔고 $4,432로 마감했습니다. Claude Opus($4,967)에 근접한 수준으로,  
**장기적 계획 수립과 자원 관리 능력이 프론티어 모델에 준한다는 것을 보여줍니다.**

## 실습: GLM-5 사용하는 방법

GLM-5는 여러 경로로 바로 사용할 수 있습니다.

### 1. Z.ai 웹 채팅

가장 간단한 방법입니다. Z.ai에 접속해 모델 옵션을 GLM-5로 변경하면 됩니다. Chat 모드(가벼운 대화)와 Agent 모드(도구 활용, 파일 생성) 두 가지를 제공합니다. Agent 모드에서는 텍스트나 원본 자료를 .docx, .pdf, .xlsx 파일로 직접 변환할 수 있습니다.

### 2. Claude Code 등 코딩 에이전트 연동

GLM-5는 Claude Code, OpenCode, Kilo Code, Roo Code, Cline 등 주요 코딩 에이전트에서 사용할 수 있습니다.

Claude Code에서 설정하는 방법은 간단합니다. `~/.claude/settings.json` 파일에서 모델명을 "GLM-5"로 변경하면 됩니다. 단, GLM Coding Plan 구독이 필요하며, 현재는 Max 플랜 사용자부터 순차적으로 지원이 확대되고 있습니다.

GLM-5 요청은 GLM-4.7보다 더 많은 플랜 쿼터를 소모한다는 점도 참고해야 합니다.

### 3. 로컬 배포

모델 가중치가 HuggingFace와 ModelScope에 MIT 라이선스로 공개되어 있습니다. vLLM과 SGLang 추론 프레임워크를 지원하며, NVIDIA GPU 외에도 화웨이 Ascend, Moore Threads, Cambricon 등 비NVIDIA 칩에서도 배포가 가능합니다.

### 4. API 호출

개발자 플랫폼 api.z.ai와 BigModel.cn에서 API로 접근할 수 있습니다. OpenAI API 호환 인터페이스를 지원하므로,  
기존 코드에서 엔드포인트와 모델명만 변경하면 대부분의 애플리케이션에 통합할 수 있습니다.

## 모범사례/패턴 비교: GLM-5 vs 경쟁 모델 선택 가이드

|  |  |  |
| --- | --- | --- |
| 웹 브라우징·검색 에이전트 | GLM-5 | BrowseComp 1위, 정보 수집·이해력 최상위 |
| 실무 코딩 (버그 수정) | Claude Opus 4.5 | SWE-bench 80.9%로 여전히 최고, 하지만 GLM-5도 77.8%로 근접 |
| 장기 계획·자원 관리 | Gemini 3.0 Pro | Vending Bench 2 $5,478로 1위 |
| 오픈소스·자체 배포 필요 | GLM-5 | MIT 라이선스, 로컬 배포 지원, 비NVIDIA 칩 호환 |
| 비용 효율 API 사용 | GLM-5 | GLM 시리즈 API 가격이 GPT-5 대비 약 1/10 수준으로 알려져 있음 |
| 수학·과학 추론 | Gemini 3.0 Pro | GPQA-Diamond 91.9%로 최고 성능 |

## 마치며

- GLM-5는 744B 파라미터(40B 활성) MoE 구조에 DeepSeek Sparse Attention과 Slime 비동기 RL을 결합해, 오픈소스 모델 중 최초로 에이전트·코딩 영역에서 프론티어 모델에 근접한 성능을 달성했습니다.
- 오픈소스 생태계의 경쟁 구도가 근본적으로 바뀌고 있습니다. "클로즈드만이 최고"라는 공식은 더 이상 유효하지 않으며, 선택의 기준이 "성능 격차"에서 "비용 대비 효율"로 이동하고 있습니다.
- 실전 팁: Z.ai에서 Agent 모드로 GLM-5를 무료 체험해보고, 기존 워크플로우에서 Claude Code 연동을 테스트해보세요.
