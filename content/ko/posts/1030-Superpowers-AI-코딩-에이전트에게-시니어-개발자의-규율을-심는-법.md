AI 코딩 에이전트에게 기능 하나를 부탁하면 어떤 일이 벌어질까요? 대부분의 경우, 에이전트는 200줄짜리 코드를 즉시 쏟아냅니다.

설계도 없고, 테스트도 없고, 유지보수성 따위는 고려 대상이 아닙니다.

결과물은 겉보기엔 작동하지만, 확장하는 순간 무너지는 코드입니다.

**Superpowers는 이 문제를 해결하기 위해 만들어진 에이전틱 스킬 프레임워크로, AI 에이전트가 "코드 생성기"가 아닌 "규율 있는 시니어 개발자"처럼 일하도록 강제합니다.**

**한줄요약:** 결론부터 말하면, Superpowers는 Claude Code 등 AI 코딩 에이전트에 설계-계획-TDD-코드리뷰 워크플로우를 자동으로 주입하여, 사람이 개입하지 않아도 수 시간 동안 체계적으로 개발할 수 있게 만드는 오픈소스 스킬 라이브러리입니다.

## 배경

AI 코딩 도구의 발전 속도는 놀랍습니다. 하지만 도구가 아무리 좋아져도, 에이전트가 따라야 할 "방법론"이 없으면 결과물의 품질은 들쭉날쭉합니다. 개발자 커뮤니티에서 반복적으로 지적되는 AI 에이전트의 고질적 문제는 크게 네 가지입니다.

**첫째**, 테스트 없는 구현입니다. 기능은 만들지만 테스트를 건너뛰는 경우가 대부분입니다.

**둘째**, 즉흥적 문제 해결입니다. 동일한 유형의 문제에도 매번 다른 방식으로 접근하고, 일관된 패턴을 따르지 않습니다.

**셋째**, 무계획 코딩입니다. 아키텍처나 영향 범위를 고려하지 않고 곧바로 코드 작성에 돌입합니다.

**넷째**, 무작위 디버깅입니다. 에러가 발생하면 원인을 분석하는 대신 이것저것 바꿔보는 시행착오에 의존합니다.

> Superpowers는 AI 코딩 에이전트에게 "설계 먼저, 계획 먼저, 테스트 먼저"라는 시니어 개발자의 규율을 마크다운 스킬 파일로 주입하는 프레임워크입니다.

2025년 10월 Jesse Vincent가 만든 이 프로젝트는 GitHub에서 약 40,900개 이상의 스타를 받았으며, Claude Code뿐 아니라 Codex, OpenCode에서도 사용할 수 있습니다.

단순한 프롬프트 모음이 아니라, 에이전트의 개발 생명주기에 깊이 통합되는 완전한 워크플로우 시스템이라는 점이 핵심입니다.

## Superpowers의 핵심 구조: 5단계 워크플로우

Superpowers가 기존 AI 코딩 도구와 근본적으로 다른 점은 "제안"이 아닌 "강제"에 있습니다. 스킬이 컨텍스트에 따라 자동으로 활성화되며, 에이전트가 이를 건너뛸 수 없습니다. 전체 워크플로우는 다섯 단계로 구성됩니다.

**1단계: 브레인스토밍(설계)** -- 코드를 작성하기 전에 활성화됩니다. 에이전트가 막연한 아이디어를 소크라테스식 질문으로 정제하고, 대안을 탐색한 뒤, 사용자가 소화할 수 있는 크기로 설계를 제시합니다. 이 단계를 통과하지 않으면 코드 작성이 시작되지 않습니다.

**2단계: Git Worktree 생성** -- 설계 승인 후, 새 브랜치에 격리된 작업 공간을 만듭니다. 깨끗한 테스트 베이스라인을 확인한 후에야 다음 단계로 넘어갑니다. 여러 에이전트가 서로 다른 기능을 동시에 작업해도 병합 충돌이 발생하지 않도록 관리합니다.

**3단계: 구현 계획 작성** -- 작업을 2~5분 단위의 작은 태스크로 분해합니다. 각 태스크에는 정확한 파일 경로, 완전한 코드, 검증 단계가 명시됩니다. 제작자인 Jesse Vincent의 표현을 빌리면, 이 계획은 "열정은 넘치지만 취향은 없고, 판단력도 없고, 테스트를 싫어하는 주니어 엔지니어"도 따라갈 수 있을 만큼 구체적이어야 합니다.

**4단계: 서브에이전트 기반 개발(실행)** -- 가장 혁신적인 단계입니다. 각 태스크마다 새로운 서브에이전트를 배치하여, 컨텍스트 오염 없이 해당 작업만 집중적으로 수행합니다. 태스크 완료 후에는 코드 리뷰 서브에이전트가 2단계 검토를 실행합니다. 스펙 준수 여부를 확인한 뒤, 코드 품질을 점검하는 방식입니다. 치명적 이슈가 발견되면 다음 태스크로 진행이 차단됩니다.

**5단계: 개발 브랜치 마무리** -- 모든 태스크가 완료되면 전체 테스트 스위트를 실행하고, 병합/PR 생성/보류/폐기 중 선택지를 사용자에게 제시합니다.

이 과정에서 에이전트가 수 시간 동안 자율적으로 작업하면서도 계획에서 벗어나지 않는 것이 Superpowers의 가장 큰 특징입니다.

## TDD 강제: "코드보다 테스트가 먼저"라는 원칙의 실체

Superpowers에서 가장 논란이 될 수도 있고, 가장 효과적이기도 한 부분은 TDD(테스트 주도 개발) 스킬입니다.

이 스킬은 단순히 "테스트를 작성하세요"라고 권유하는 수준이 아닙니다. 에이전트가 테스트 없이 먼저 코드를 작성하면,

해당 코드를 삭제하도록 강제합니다.

RED-GREEN-REFACTOR 사이클을 따릅니다. 먼저 실패하는 테스트를 작성하고(RED), 그 테스트를 통과시키는 최소한의 코드만 구현한 뒤(GREEN), 테스트가 통과하는 상태를 유지하면서 리팩터링합니다(REFACTOR).

이 스킬에는 에이전트가 TDD를 회피하려 할 때 사용하는 핑계 목록과 그에 대한 반론이 내장되어 있습니다.

"너무 단순해서 테스트가 필요 없다"거나, "나중에 테스트를 작성하겠다"거나, "정신만 따르면 된다"는 식의 합리화를 차단합니다.

이는 사람 개발자에게도 익숙한 핑계들이라는 점에서, 이 스킬의 설계가 현실의 개발 문화를 깊이 이해하고 있음을 보여줍니다.

## 스킬 시스템: "마크다운 파일이 곧 방법론"

Superpowers의 핵심 메커니즘은 **스킬(Skill)** 시스템입니다. 스킬은 마크다운 파일(SKILL.md)로 작성된 참조 가이드이며, 에이전트가 컨텍스트에 따라 자동으로 로딩합니다. 이 접근 방식이 흥미로운 이유는, 코드가 아닌 문서가 에이전트의 행동을 제어한다는 점입니다.

스킬은 크게 네 가지 카테고리로 구성됩니다.

| 카테고리 | 포함된 스킬 | 핵심 역할 |
| --- | --- | --- |
| 테스팅 | test-driven-development | RED-GREEN-REFACTOR 사이클, 안티패턴 참조 |
| 디버깅 | systematic-debugging, verification-before-completion | 4단계 근본 원인 분석, 수정 후 검증 |
| 협업 | brainstorming, writing-plans, executing-plans, subagent-driven-development 등 | 설계 정제, 계획 작성, 서브에이전트 병렬 작업, 코드리뷰 |
| 메타 | writing-skills, using-superpowers | 새 스킬 작성, 스킬 시스템 소개 |

주목할 점은 writing-skills 스킬입니다. 이 스킬은 "스킬을 만드는 방법"을 가르치는 메타 스킬인데, 여기에도 TDD 원칙이 적용됩니다.

새로운 스킬을 작성할 때, 서브에이전트로 테스트 시나리오를 만들어 해당 스킬 없이 실패하는 것을 확인한 뒤,

스킬을 작성하고 통과하는지 검증합니다. Jesse Vincent는 이를 "문서를 위한 TDD"라고 부릅니다.

## 설치와 사용

Claude Code 사용자라면 설치가 매우 간단합니다. 터미널에서 두 줄의 명령어면 충분합니다.

```
# Claude Code 플러그인 마켓플레이스 등록
/plugin marketplace add obra/superpowers-marketplace

# Superpowers 설치
/plugin install superpowers@superpowers-marketplace
```

설치 후 Claude Code를 재시작하면, 세션 시작 시 Superpowers 부트스트랩이 자동으로 주입됩니다.

별도의 설정 없이 "help me plan this feature"나 "let's debug this issue" 같은 요청을 하면 관련 스킬이 자동 활성화됩니다.

Codex나 OpenCode의 경우, GitHub 저장소를 클론하고 심볼릭 링크를 설정하는 수동 설치 과정이 필요합니다.

자세한 방법은 공식 문서에서 확인할 수 있습니다.

설치 검증은 `/help` 명령어로 가능합니다. `superpowers:brainstorm`, `superpowers:write-plan`, `superpowers:execute-plan` 커맨드가 표시되면 정상 설치된 것입니다.

## Superpowers가 적합한 경우와 아닌 경우

| 적합한 경우 | 적합하지 않은 경우 |
| --- | --- |
| 2시간 이상 소요되는 복잡한 기능 개발 | 빠른 프로토타이핑이나 단순 리팩터링 |
| 높은 테스트 커버리지가 필요한 프로덕션 코드 | 실험적이고 탐색적인 코딩 |
| 일관된 코드 품질이 요구되는 팀 프로젝트 | TDD와 다른 개발 방법론을 선호하는 경우 |
| 체계적 디버깅이 필요한 복잡한 버그 | 에이전트의 자유도를 최대한 활용하고 싶은 경우 |

Superpowers는 매우 의견이 강한(opinionated) 프레임워크입니다. 이 점이 장점이자 단점입니다.

TDD를 비롯한 특정 방법론을 강제하기 때문에, 자신만의 워크플로우가 있는 개발자에게는 제약으로 느껴질 수 있습니다.

반면, AI 에이전트가 일관된 품질을 유지하길 원하는 개발자에게는 구조화된 워크플로우가 시간 절약으로 직결됩니다.

## 마치며

- Superpowers는 AI 코딩 에이전트에게 설계-계획-TDD-코드리뷰로 이어지는 시니어 개발자의 워크플로우를 강제하는 오픈소스 스킬 프레임워크입니다.
- 서브에이전트 기반 개발은 각 태스크마다 새로운 에이전트를 배치하고 2단계 코드 리뷰를 자동 수행함으로써, 수 시간의 자율 개발에서도 품질을 유지합니다.
- 실전 팁: Claude Code 사용자라면 오늘 당장 `/plugin install superpowers@superpowers-marketplace`를 실행하고, 다음 기능 개발에서 에이전트가 설계부터 시작하는지 확인해보세요.
