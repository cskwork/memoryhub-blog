RAG 시스템을 구축할 때 가장 먼저 부딪히는 문제가 있다. 임베딩 저장공간이다. 100GB 텍스트를 인덱싱하면 인덱스가 150~700GB까지 불어난다. 원본보다 인덱스가 더 크다는 말이다.

노트북에서 개인 AI를 돌리고 싶은데, 벡터 DB가 디스크를 잡아먹는다면?

2025년 등장한 두 기술이 이 문제에 정반대 방식으로 답한다.

**임베딩을 저장할 것인가, 쿼리할 때마다 다시 계산할 것인가. 이 선택이 저장공간, 속도, 운영 복잡도를 결정한다.**

**한줄요약:** 결론부터 말하면, 디스크가 병목이면 LEANN, 운영 단순성이 우선이면 Memvid다.

## 배경

RAG(Retrieval-Augmented Generation)는 LLM의 환각을 줄이고 최신 정보를 활용하는 핵심 기술로 자리 잡았다. 문제는 RAG가 필연적으로 벡터 검색을 수반한다는 점이다. 텍스트를 임베딩 벡터로 변환하고,

이 벡터들을 저장하고, 유사한 벡터를 찾아야 한다.

> 벡터 인덱스의 저장 오버헤드는 원본 데이터의 1.5배에서 7배에 달한다.

기존 벡터 DB들(Pinecone, Weaviate, Chroma 등)은 대부분 "임베딩을 미리 계산해서 저장한다"는 전제 위에 설계되었다. 데이터센터 환경에서는 이게 합리적이다. 저장공간이 저렴하고, 검색 속도가 최우선이니까.

하지만 개인 디바이스나 엣지 환경에서는 이야기가 달라진다. 노트북 SSD 512GB에 개인 문서 100GB를 인덱싱했더니 인덱스가 400GB? 현실적으로 불가능하다.

이 문제에 2025년 두 가지 상반된 접근법이 등장했다. Memvid는 "단일 파일로 패키징하되 임베딩은 저장한다"는 방향이고, LEANN은 "임베딩을 아예 저장하지 않고 필요할 때 계산한다"는 방향이다.

## Memvid: 단일 파일에 모든 것을 담다

Memvid의 핵심 아이디어는 "포터블리티"다. 데이터, 임베딩, 검색 구조, 메타데이터를 하나의 `.mv2` 파일에 패키징한다. 복잡한 RAG 파이프라인 대신, 파일 하나만 있으면 어디서든 검색이 가능하다.

Memvid는 비디오 인코딩에서 영감을 받았다. 텍스트를 "Smart Frame"이라는 불변 단위로 저장한다. 각 프레임에는 콘텐츠, 타임스탬프, 체크섬, 메타데이터가 담긴다. 프레임들은 효율적인 압축, 인덱싱, 병렬 읽기가 가능하도록 그룹화된다.

검색 측면에서 Memvid는 **하이브리드 검색**을 기본 제공한다. BM25 기반 렉시컬 검색과 HNSW 기반 시맨틱 검색을 모두 지원한다. 로컬 임베딩은 ONNX 모델(BGE, Nomic 등)을 사용하며, 완전히 오프라인으로 동작한다.

Rust로 재작성된 v2.0 이후 성능이 크게 개선되었다. 공식 문서에 따르면 Python 버전 대비 10~100배 빠른 성능을 보인다. "sub-5ms 로컬 메모리 접근"이라는 표현이 등장하는데,

이는 캐시된 상태에서의 순수 메모리 접근 시간을 의미하며 임베딩 계산을 포함한 엔드투엔드 지연시간과는

다르다는 점에 주의가 필요하다.

하지만 Memvid의 한계도 명확하다.

**임베딩을 저장한다는 기본 설계** 때문에, 코퍼스가 커질수록 저장공간 문제가 발생한다.

FP32 임베딩 기준으로 N개 청크, d차원이면 임베딩만으로 N × d × 4 바이트가 필요하다. 100만 개 청크, 768차원이면 약 3GB다. 여기에 HNSW 그래프 메타데이터가 추가된다.

## LEANN: 임베딩을 저장하지 않는다

LEANN(Low-Storage Embedding Approximate Nearest Neighbor)은 근본적으로 다른 접근을 취한다. 임베딩을 디스크에 저장하지 않고, 쿼리 시점에 필요한 노드의 임베딩만 **온더플라이로 재계산**한다.

LEANN의 핵심 통찰은 이렇다. HNSW 같은 그래프 기반 인덱스에서 쿼리 하나가 실제로 방문하는 노드는 전체의 일부에 불과하다. 전체 임베딩을 저장할 필요가 없다. 방문하는 노드만 그때그때 계산하면 된다.

UC Berkeley, CUHK, AWS, UC Davis 연구진이 개발한 이 방법은 두 가지 핵심 기술을 사용한다.

첫째, **2단계 그래프 순회와 동적 배칭**으로 재계산 지연시간을 줄인다.

둘째, **고차수 노드 보존 프루닝**으로 그래프 메타데이터 오버헤드를 최소화한다.

결과는 놀랍다. 논문에 따르면 LEANN은 **원본 데이터의 5% 미만 저장공간**으로 동작하면서, 90% top-3 recall을 달성한다. 기존 인덱스 대비 최대 50배 저장공간을 줄인다.

EdgeRAG 같은 기존 재계산 기반 방법 대비 21~200배 빠른 지연시간을 보인다.

다만 LEANN에도 트레이드오프가 있다. 쿼리마다 임베딩을 재계산하므로 **지연시간이 증가**한다. 논문은 "90% top-3 recall에서 엔드투엔드 2초 미만"이라는 결과를 제시한다. 데이터센터 기준으로는 느리지만, 개인 디바이스에서 수십 초 걸리는 이미지/텍스트 생성 작업과 비교하면 합리적인 수준이라는 것이 연구진의 주장이다.

## 저장공간 vs 연산: 수식으로 보는 트레이드오프

두 접근의 차이를 수식으로 정리하면 명확해진다. 텍스트 청크 수를 N, 임베딩 차원을 d, 원소당 바이트를 b(FP32면 4)라 하자.

**Memvid 방식(임베딩 저장)의 저장공간:**

```
S_total ≈ S_data + N × d × b + S_graph_metadata
```

**LEANN 방식(임베딩 미저장)의 저장공간:**

```
S_total ≈ S_data + S_pruned_graph (목표: S_data의 5% 이하)
```

쿼리 지연시간도 다르다.

**Memvid의 쿼리 지연시간:**

```
T ≈ T_embed_query + T_hnsw_search
```

**LEANN의 쿼리 지연시간:**

```
T ≈ T_graph_traversal + |C| × T_embed + T_rerank
```

여기서 |C|는 탐색 중 임베딩 재계산이 필요한 후보 노드 수다. LEANN은 이 부분을 배칭과 프루닝으로 최적화한다.

## 언제 무엇을 선택할 것인가

| 상황 | 권장 선택 | 이유 |
| --- | --- | --- |
| 저장공간이 절대적 제약 (노트북, 엣지 디바이스) | LEANN | 원본 대비 5% 저장공간 |
| 단일 파일 배포, git commit/scp 필요 | Memvid | .mv2 파일 하나로 완결 |
| 하이브리드 검색(BM25+벡터) 필수 | Memvid | 기본 내장 |
| 수천만 청크 이상 대규모 코퍼스 | LEANN | 저장공간 선형 증가 회피 |
| 빠른 응답 속도 최우선 | Memvid | 재계산 오버헤드 없음 |
| 완전 오프라인 동작 필요 | 둘 다 가능 | 로컬 임베딩 모델 지원 |

실제 프로젝트에서는 데이터 규모를 먼저 파악해야 한다. 청크 100만 개, 768차원, FP32 기준으로 Memvid는 약 3GB의 임베딩 저장공간이 필요하다. LEANN은 원본 데이터의 5% 정도만 필요하다.

청크당 평균 500바이트라면 원본이 500MB, LEANN 인덱스는 25MB 수준이다.

응답 속도도 고려해야 한다. Memvid는 밀리초 단위 응답이 가능하다. LEANN은 90% recall 기준 2초 내외다. 실시간 챗봇에는 Memvid가, 배치 검색이나 비실시간 워크로드에는 LEANN이 적합하다.

## 모범사례/패턴 비교

| 패턴 | 장점 | 주의점 |
| --- | --- | --- |
| Memvid + 로컬 ONNX 임베딩 | 완전한 오프라인 동작, 설정 단순 | 대규모 코퍼스에서 저장공간 급증 |
| LEANN + 작은 임베딩 모델 | 극단적 저장공간 절약, 엣지 배포 가능 | 쿼리 지연시간 증가 |
| Memvid + 하이브리드 검색 | 키워드+시맨틱 동시 검색 | 인덱스 크기 추가 증가 |
| LEANN + 핫 캐싱 | 자주 접근하는 임베딩 캐시로 지연시간 감소 | 메모리 사용량 증가 |

## 마치며

- Memvid와 LEANN은 RAG 저장공간 문제에 대한 정반대 해답이다. 하나는 모든 것을 저장하되 패키징을 최적화하고, 다른 하나는 저장 자체를 피한다.
- 두 기술 모두 2025년 등장한 신생 프로젝트다. 프로덕션 적용 시 벤치마크와 엣지 케이스 검증이 필수다.
- 실전 팁: 먼저 자신의 코퍼스 규모와 디바이스 제약을 계산하고, 예상 저장공간이 감당 가능한지 확인한 후 기술을 선택하라.
