클로드 코드의 새로운 샌드박싱 기능, bash 도구, 그리고 웹 기반 클로드 코드는 파일시스템과 네트워크 격리라는 두 가지 경계를 통해 권한 요청을 줄이고 사용자 안전성을 높입니다.

클로드 코드에서 클로드는 사용자와 함께 코드를 작성하고 테스트하며 디버깅합니다. 코드베이스를 탐색하고 여러 파일을 편집하며 명령을 실행해서 작업을 검증하죠. 클로드에게 코드베이스와 파일에 대한 이런 광범위한 접근 권한을 부여하면 특히 프롬프트 인젝션의 경우 위험이 발생할 수 있습니다.

이 문제를 해결하기 위해 샌드박싱 기반의 두 가지 새 기능을 클로드 코드에 도입했습니다.

두 기능 모두 개발자에게 더 안전한 작업 환경을 제공하면서 클로드가 더 자율적으로 작동하고 권한 요청을 줄일 수 있도록 설계되었습니다. 내부 사용 결과, 샌드박싱이 권한 요청을 84%나 안전하게 줄인다는 것을 확인했습니다.

클로드가 자유롭게 작업할 수 있는 명확한 경계를 정의함으로써 보안과 자율성이 모두 향상됩니다.

## 클로드 코드에서 사용자 보안 유지하기

클로드 코드는 권한 기반 모델로 작동합니다. 기본적으로 읽기 전용이며, 수정이나 명령 실행 전에 권한을 요청합니다. 물론 예외도 있습니다. echo나 cat 같은 안전한 명령은 자동으로 허용하지만, 대부분의 작업에는 여전히 명시적 승인이 필요합니다.

계속해서 "승인"을 클릭하는 것은 개발 주기를 늦추고 '승인 피로'로 이어질 수 있습니다. 사용자가 무엇을 승인하는지 주의 깊게 살피지 않게 되면서 오히려 개발이 덜 안전해지는 거죠.

이를 해결하기 위해 클로드 코드용 샌드박싱을 출시했습니다.

## 샌드박싱: 더 안전하고 자율적인 접근법

샌드박싱은 각 작업마다 권한을 요청하는 대신, 클로드가 더 자유롭게 작업할 수 있는 미리 정의된 경계를 만듭니다. 샌드박싱을 활성화하면 권한 요청이 대폭 줄어들고 안전성은 높아집니다.

샌드박싱 접근 방식은 운영체제 수준 기능을 기반으로 두 가지 경계를 구현합니다:

**파일시스템 격리**는 클로드가 특정 디렉토리만 접근하거나 수정할 수 있도록 합니다. 프롬프트 인젝션을 당한 클로드가 중요한 시스템 파일을 수정하는 것을 방지하는 데 특히 중요합니다.

**네트워크 격리**는 클로드가 승인된 서버에만 연결할 수 있도록 합니다. 프롬프트 인젝션을 당한 클로드가 민감한 정보를 유출하거나 악성코드를 다운로드하는 것을 방지합니다.

효과적인 샌드박싱에는 파일시스템과 네트워크 격리가 모두 필요하다는 점이 중요합니다. 네트워크 격리가 없으면 손상된 에이전트가 SSH 키 같은 민감한 파일을 유출할 수 있고, 파일시스템 격리가 없으면 손상된 에이전트가 쉽게 샌드박스를 벗어나 네트워크에 접근할 수 있습니다. 두 기술을 함께 사용해야 클로드 코드 사용자에게 더 안전하고 빠른 에이전트 경험을 제공할 수 있습니다.

## 클로드 코드의 두 가지 새로운 샌드박싱 기능

### 샌드박스 bash 도구: 권한 요청 없는 안전한 bash 실행

새로운 샌드박스 런타임을 베타 연구 프리뷰로 출시합니다. 컨테이너를 설정하고 관리하는 오버헤드 없이 에이전트가 접근할 수 있는 디렉토리와 네트워크 호스트를 정확하게 정의할 수 있습니다. 임의의 프로세스, 에이전트, MCP 서버를 샌드박스화할 수 있으며, 오픈소스 연구 프리뷰로도 제공됩니다.

클로드 코드에서는 이 런타임을 사용해서 bash 도구를 샌드박스화합니다. 클로드가 설정한 제한 내에서 명령을 실행할 수 있도록 하죠. 안전한 샌드박스 내에서 클로드는 더 자율적으로 작동하며 권한 요청 없이 안전하게 명령을 실행할 수 있습니다. 클로드가 샌드박스 밖의 무언가에 접근하려고 하면 즉시 알림을 받고, 허용 여부를 선택할 수 있습니다.

Linux bubblewrap이나 MacOS seatbelt 같은 OS 수준 프리미티브를 기반으로 구축했습니다. 이러한 제한은 OS 수준에서 적용되며, 클로드 코드의 직접 상호작용뿐만 아니라 명령으로 생성된 스크립트, 프로그램, 하위 프로세스까지 모두 포함합니다. 위에서 설명한 것처럼

이 샌드박스는 다음 두 가지를 모두 적용합니다:

**파일시스템 격리**: 현재 작업 디렉토리에 대한 읽기 및 쓰기 접근은 허용하지만, 그 외부의 파일 수정은 차단합니다.

**네트워크 격리**: 샌드박스 외부에서 실행되는 프록시 서버에 연결된 유닉스 도메인 소켓을 통해서만 인터넷 접근을 허용합니다. 이 프록시 서버는 프로세스가 연결할 수 있는 도메인에 대한 제한을 적용하고, 새로 요청된 도메인에 대한 사용자 확인을 처리합니다. 더 강화된 보안이 필요하다면 이 프록시를 커스터마이징해서 나가는 트래픽에 임의의 규칙을 적용할 수도 있습니다.

두 구성 요소 모두 설정 가능합니다. 특정 파일 경로나 도메인을 쉽게 허용하거나 차단할 수 있습니다.

![](/images/863-Claude-Code-샌드박스-기능/img.webp)

클로드 코드의 샌드박싱 아키텍처는 파일시스템과 네트워크 제어로 코드 실행을 격리하여, 안전한 작업은 자동으로 허용하고 악의적인 작업은 차단하며 필요한 경우에만 권한을 요청합니다.

샌드박싱은 프롬프트 인젝션이 성공하더라도 완전히 격리되어 전체 사용자 보안에 영향을 미치지 않도록 합니다. 손상된 클로드 코드가 SSH 키를 훔치거나 공격자의 서버로 정보를 전송할 수 없는 거죠.

이 기능을 사용하려면 클로드 코드에서 `/sandbox`를 실행하고, 보안 모델에 대한 자세한 기술 문서를 확인하세요.

다른 팀들이 더 안전한 에이전트를 만들 수 있도록 이 기능을 오픈소스로 공개했습니다. 다른 팀들도 자신들의 에이전트 보안 태세를 강화하기 위해 이 기술을 도입하는 것을 고려해주시길 바랍니다.

### 웹 기반 클로드 코드: 클라우드에서 클로드 코드를 안전하게 실행

오늘 웹 기반 클로드 코드를 출시합니다. 클라우드의 격리된 샌드박스에서 클로드 코드를 실행할 수 있습니다. 웹 기반 클로드 코드는 각 세션을 격리된 샌드박스에서 실행하며, 클로드가 안전하고 안전하게 서버에 완전히 접근할 수 있습니다. git 자격 증명이나 서명 키 같은 민감한 자격 증명이 클로드 코드와 함께 샌드박스 안에 절대 들어가지 않도록 설계했습니다. 샌드박스에서 실행되는 코드가 손상되더라도 사용자는 추가 피해로부터 안전하게 보호됩니다.

웹 기반 클로드 코드는 모든 git 상호작용을 투명하게 처리하는 커스텀 프록시 서비스를 사용합니다. 샌드박스 내부에서 git 클라이언트는 커스텀 제작된 범위 지정 자격 증명으로 이 서비스에 인증합니다. 프록시는 이 자격 증명과 git 상호작용의 내용(예: 설정된 브랜치로만 푸시하는지 확인)을 검증한 다음, GitHub에 요청을 보내기 전에 올바른 인증 토큰을 첨부합니다.

![](/images/863-Claude-Code-샌드박스-기능/img_1.webp)

클로드 코드의 Git 통합은 인증 토큰, 브랜치 이름, 저장소 대상을 검증하는 보안 프록시를 통해 명령을 라우팅하여, 무단 푸시를 방지하면서 안전한 버전 관리 워크플로를 제공합니다.

## 시작하기

새로운 샌드박스 bash 도구와 웹 기반 클로드 코드는 개발자들이 클로드를 엔지니어링 작업에 사용할 때 보안과 생산성 모두에서 상당한 개선을 제공합니다.

도구 사용을 시작하려면:

- 클로드에서 `/sandbox`를 실행하고 샌드박스 구성 방법에 대한 문서를 확인하세요.
- claude.com/code로 가서 웹 기반 클로드 코드를 사용해보세요.
- 또는 자체 에이전트를 구축 중이라면 오픈소스 샌드박싱 코드를 확인하고 작업에 통합하는 것을 고려해보세요. 어떤 것을 만드시는지 기대하겠습니다.

웹 기반 클로드 코드에 대해 더 자세히 알고 싶으시면 출시 블로그 게시물을 확인하세요.
