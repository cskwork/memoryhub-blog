직접적인 도구 호출은 각 정의와 결과마다 컨텍스트를 소비합니다. 에이전트는 대신 도구를 호출하는 코드를 작성함으로써 더 효과적으로 확장됩니다. MCP에서 이를 구현하는 방법은 다음과 같습니다.

Model Context Protocol(MCP)은 AI 에이전트를 외부 시스템에 연결하기 위한 개방형 표준입니다. 에이전트를 도구와 데이터에 연결하는 것은 전통적으로 각 쌍마다 맞춤형 통합이 필요했고, 이는 분산과 중복 작업을 초래하여 진정으로 연결된 시스템을 확장하기 어렵게 만들었습니다. MCP는 범용 프로토콜을 제공합니다. 개발자가 에이전트에 MCP를 한 번 구현하면 전체 통합 생태계가 열립니다.

2024년 11월 MCP 출시 이후 채택이 빠르게 이루어졌습니다. 커뮤니티는 수천 개의 MCP 서버를 구축했고, 모든 주요 프로그래밍 언어에 대한 SDK를 사용할 수 있으며, 업계는 MCP를 에이전트를 도구 및 데이터에 연결하는 사실상의 표준으로 채택했습니다.

오늘날 개발자들은 수십 개의 MCP 서버에 걸쳐 수백 또는 수천 개의 도구에 액세스할 수 있는 에이전트를 정기적으로 구축합니다. 그러나 연결된 도구의 수가 증가함에 따라 모든 도구 정의를 미리 로드하고 중간 결과를 컨텍스트 윈도우를 통해 전달하는 것은 에이전트 속도를 저하시키고 비용을 증가시킵니다.

이 블로그에서는 코드 실행이 에이전트가 MCP 서버와 더 효율적으로 상호 작용할 수 있도록 하여 더 적은 토큰으로 더 많은 도구를 처리하는 방법을 살펴봅니다.

## 도구의 과도한 토큰 소비가 에이전트 효율성을 저하시킵니다

MCP 사용이 확장됨에 따라 에이전트 비용과 지연 시간을 증가시킬 수 있는 두 가지 일반적인 패턴이 있습니다:

1. 도구 정의가 컨텍스트 윈도우를 과부하시킴
2. 중간 도구 결과가 추가 토큰을 소비함

### 1. 도구 정의가 컨텍스트 윈도우를 과부하시킴

대부분의 MCP 클라이언트는 모든 도구 정의를 미리 컨텍스트에 직접 로드하여 직접 도구 호출 구문을 사용해 모델에 노출합니다. 이러한 도구 정의는 다음과 같을 수 있습니다:

```
gdrive.getDocument
     설명: Google Drive에서 문서를 검색합니다
     매개변수:
                documentId (필수, 문자열): 검색할 문서의 ID
                fields (선택, 문자열): 반환할 특정 필드
     반환값: 제목, 본문 내용, 메타데이터, 권한 등이 포함된 문서 객체

salesforce.updateRecord
    설명: Salesforce의 레코드를 업데이트합니다
    매개변수:
               objectType (필수, 문자열): Salesforce 객체 유형(Lead, Contact, Account 등)
               recordId (필수, 문자열): 업데이트할 레코드의 ID
               data (필수, 객체): 새 값으로 업데이트할 필드
     반환값: 확인이 포함된 업데이트된 레코드 객체
```

도구 설명은 더 많은 컨텍스트 윈도우 공간을 차지하여 응답 시간과 비용을 증가시킵니다. 에이전트가 수천 개의 도구에 연결된 경우, 요청을 읽기 전에 수십만 개의 토큰을 처리해야 합니다.

### 2. 중간 도구 결과가 추가 토큰을 소비함

대부분의 MCP 클라이언트는 모델이 MCP 도구를 직접 호출할 수 있도록 합니다. 예를 들어, 에이전트에게 "Google Drive에서 회의 녹취록을 다운로드하여 Salesforce 리드에 첨부해줘"라고 요청할 수 있습니다.

모델은 다음과 같은 호출을 수행합니다:

```
TOOL CALL: gdrive.getDocument(documentId: "abc123")
        → "Q4 목표에 대해 논의...\n[전체 녹취록 텍스트]" 반환
           (모델 컨텍스트에 로드됨)

TOOL CALL: salesforce.updateRecord(
            objectType: "SalesMeeting",
            recordId: "00Q5f000001abcXYZ",
              data: { "Notes": "Q4 목표에 대해 논의...\n[전체 녹취록 텍스트 작성됨]" }
        )
        (모델이 전체 녹취록을 컨텍스트에 다시 작성해야 함)
```

모든 중간 결과는 모델을 통과해야 합니다. 이 예에서 전체 통화 녹취록은 두 번 흐릅니다. 2시간짜리 영업 회의의 경우 추가로 50,000개의 토큰을 처리해야 할 수 있습니다. 더 큰 문서는 컨텍스트 윈도우 제한을 초과하여 워크플로를 중단시킬 수 있습니다.

대용량 문서나 복잡한 데이터 구조를 다룰 때, 모델은 도구 호출 간에 데이터를 복사할 때 실수를 할 가능성이 더 높습니다.

**MCP 클라이언트가 MCP 서버 및 LLM과 작동하는 방식의 이미지**

MCP 클라이언트는 도구 정의를 모델의 컨텍스트 윈도우에 로드하고, 각 도구 호출과 결과가 작업 간에 모델을 통과하는 메시지 루프를 조율합니다.

## MCP를 사용한 코드 실행이 컨텍스트 효율성을 향상시킵니다

코드 실행 환경이 에이전트에 더 일반화되면서, 해결책은 MCP 서버를 직접 도구 호출이 아닌 코드 API로 제공하는 것입니다. 그러면 에이전트는 MCP 서버와 상호 작용하는 코드를 작성할 수 있습니다. 이 접근 방식은 두 가지 문제를 모두 해결합니다. 에이전트는 필요한 도구만 로드할 수 있고, 결과를 모델에 다시 전달하기 전에 실행 환경에서 데이터를 처리할 수 있습니다.

이를 수행하는 방법은 여러 가지가 있습니다. 한 가지 접근 방식은 연결된 MCP 서버에서 사용 가능한 모든 도구의 파일 트리를 생성하는 것입니다. TypeScript를 사용한 구현은 다음과 같습니다:

```
servers
├── google-drive
│   ├── getDocument.ts
│   ├── ... (기타 도구)
│   └── index.ts
├── salesforce
│   ├── updateRecord.ts
│   ├── ... (기타 도구)
│   └── index.ts
└── ... (기타 서버)
```

그런 다음 각 도구는 다음과 같은 파일에 해당합니다:

```
// ./servers/google-drive/getDocument.ts
import { callMCPTool } from "../../../client.js";

interface GetDocumentInput {
  documentId: string;
}

interface GetDocumentResponse {
  content: string;
}

/* Google Drive에서 문서 읽기 */
export async function getDocument(input: GetDocumentInput): Promise<GetDocumentResponse> {
  return callMCPTool<GetDocumentResponse>('google_drive__get_document', input);
}
```

위의 Google Drive에서 Salesforce로 가는 예제는 다음 코드가 됩니다:

```
// Google Docs에서 녹취록을 읽고 Salesforce 잠재 고객에 추가
import * as gdrive from './servers/google-drive';
import * as salesforce from './servers/salesforce';

const transcript = (await gdrive.getDocument({ documentId: 'abc123' })).content;
await salesforce.updateRecord({
  objectType: 'SalesMeeting',
  recordId: '00Q5f000001abcXYZ',
  data: { Notes: transcript }
});
```

에이전트는 파일 시스템을 탐색하여 도구를 발견합니다. `./servers/` 디렉토리를 나열하여 사용 가능한 서버(예: google-drive 및 salesforce)를 찾은 다음, 필요한 특정 도구 파일(예: getDocument.ts 및 updateRecord.ts)을 읽어 각 도구의 인터페이스를 이해합니다. 이를 통해 에이전트는 현재 작업에 필요한 정의만 로드할 수 있습니다. 이는 토큰 사용량을 150,000개 토큰에서 2,000개 토큰으로 줄여 시간과 비용을 98.7% 절감합니다.

Cloudflare도 유사한 결과를 발표하며 MCP를 사용한 코드 실행을 "코드 모드"라고 불렀습니다. 핵심 통찰은 동일합니다. LLM은 코드 작성에 능숙하며 개발자는 이 강점을 활용하여 MCP 서버와 더 효율적으로 상호 작용하는 에이전트를 구축해야 합니다.

## MCP를 사용한 코드 실행의 이점

MCP를 사용한 코드 실행은 에이전트가 필요에 따라 도구를 로드하고, 모델에 도달하기 전에 데이터를 필터링하고, 한 단계에서 복잡한 로직을 실행하여 컨텍스트를 더 효율적으로 사용할 수 있도록 합니다. 이 접근 방식을 사용하면 보안 및 상태 관리 이점도 있습니다.

### 점진적 공개

모델은 파일 시스템 탐색에 능숙합니다. 도구를 파일 시스템의 코드로 제공하면 모델이 모든 도구 정의를 미리 읽지 않고 필요에 따라 읽을 수 있습니다.

또는 `search_tools` 도구를 서버에 추가하여 관련 정의를 찾을 수 있습니다. 예를 들어, 위에서 사용된 가상의 Salesforce 서버로 작업할 때 에이전트는 "salesforce"를 검색하고 현재 작업에 필요한 도구만 로드합니다. `search_tools` 도구에 세부 수준 매개변수를 포함하여 에이전트가 필요한 세부 수준(이름만, 이름 및 설명, 또는 스키마가 포함된 전체 정의)을 선택할 수 있도록 하면 에이전트가 컨텍스트를 절약하고 도구를 효율적으로 찾을 수 있습니다.

### 컨텍스트 효율적인 도구 결과

대용량 데이터셋으로 작업할 때 에이전트는 결과를 반환하기 전에 코드에서 필터링하고 변환할 수 있습니다. 10,000행 스프레드시트를 가져오는 경우를 고려해보세요:

```
// 코드 실행 없이 - 모든 행이 컨텍스트를 통과
TOOL CALL: gdrive.getSheet(sheetId: 'abc123')
        → 수동으로 필터링하기 위해 컨텍스트에서 10,000개 행 반환

// 코드 실행 사용 - 실행 환경에서 필터링
const allRows = await gdrive.getSheet({ sheetId: 'abc123' });
const pendingOrders = allRows.filter(row => 
  row["Status"] === 'pending'
);
console.log(`${pendingOrders.length}개의 대기 중인 주문 발견`);
console.log(pendingOrders.slice(0, 5)); // 검토를 위해 처음 5개만 로그
```

에이전트는 10,000개 행 대신 5개 행만 봅니다. 유사한 패턴은 집계, 여러 데이터 소스 간 조인, 특정 필드 추출에도 작동하며 모두 컨텍스트 윈도우를 팽창시키지 않습니다.

### 더 강력하고 컨텍스트 효율적인 제어 흐름

루프, 조건문, 오류 처리는 개별 도구 호출을 연결하는 대신 익숙한 코드 패턴으로 수행할 수 있습니다. 예를 들어, Slack에서 배포 알림이 필요한 경우 에이전트는 다음을 작성할 수 있습니다:

```
let found = false;
while (!found) {
  const messages = await slack.getChannelHistory({ channel: 'C123456' });
  found = messages.some(m => m.text.includes('deployment complete'));
  if (!found) await new Promise(r => setTimeout(r, 5000));
}
console.log('배포 알림 수신됨');
```

이 접근 방식은 에이전트 루프를 통해 MCP 도구 호출과 sleep 명령을 번갈아 사용하는 것보다 더 효율적입니다.

또한 실행되는 조건부 트리를 작성할 수 있으면 "첫 번째 토큰까지의 시간" 지연 시간도 절약됩니다. 모델이 if 문을 평가하기를 기다리는 대신 에이전트가 코드 실행 환경이 이를 수행하도록 할 수 있습니다.

### 개인정보 보호 작업

에이전트가 MCP와 함께 코드 실행을 사용하면 중간 결과는 기본적으로 실행 환경에 남아 있습니다. 이렇게 하면 에이전트는 명시적으로 로그하거나 반환하는 것만 볼 수 있으며, 모델과 공유하고 싶지 않은 데이터는 모델의 컨텍스트에 들어가지 않고 워크플로를 통과할 수 있습니다.

더욱 민감한 워크로드의 경우 에이전트 하네스가 민감한 데이터를 자동으로 토큰화할 수 있습니다. 예를 들어, 스프레드시트에서 Salesforce로 고객 연락처 세부 정보를 가져와야 한다고 가정해보세요. 에이전트는 다음을 작성합니다:

```
const sheet = await gdrive.getSheet({ sheetId: 'abc123' });
for (const row of sheet.rows) {
  await salesforce.updateRecord({
    objectType: 'Lead',
    recordId: row.salesforceId,
    data: { 
      Email: row.email,
      Phone: row.phone,
      Name: row.name
    }
  });
}
console.log(`${sheet.rows.length}개의 리드 업데이트됨`);
```

MCP 클라이언트는 데이터를 가로채고 모델에 도달하기 전에 PII를 토큰화합니다:

```
// sheet.rows를 로그한 경우 에이전트가 볼 내용:
[
  { salesforceId: '00Q...', email: '[EMAIL_1]', phone: '[PHONE_1]', name: '[NAME_1]' },
  { salesforceId: '00Q...', email: '[EMAIL_2]', phone: '[PHONE_2]', name: '[NAME_2]' },
  ...
]
```

그런 다음 데이터가 다른 MCP 도구 호출에서 공유되면 MCP 클라이언트의 조회를 통해 토큰화가 해제됩니다. 실제 이메일 주소, 전화번호, 이름은 Google Sheets에서 Salesforce로 흐르지만 모델을 통과하지는 않습니다. 이는 에이전트가 실수로 민감한 데이터를 로깅하거나 처리하는 것을 방지합니다. 또한 이를 사용하여 데이터가 흐를 수 있는 위치와 출처를 선택하는 결정적 보안 규칙을 정의할 수 있습니다.

### 상태 지속성 및 스킬

파일 시스템 액세스를 통한 코드 실행을 통해 에이전트는 작업 전반에 걸쳐 상태를 유지할 수 있습니다. 에이전트는 중간 결과를 파일에 작성하여 작업을 재개하고 진행 상황을 추적할 수 있습니다:

```
const leads = await salesforce.query({ 
  query: 'SELECT Id, Email FROM Lead LIMIT 1000' 
});
const csvData = leads.map(l => `${l.Id},${l.Email}`).join('\n');
await fs.writeFile('./workspace/leads.csv', csvData);

// 나중에 실행하면 중단된 지점에서 계속
const saved = await fs.readFile('./workspace/leads.csv', 'utf-8');
```

에이전트는 자체 코드를 재사용 가능한 함수로 유지할 수도 있습니다. 에이전트가 작업에 대한 작동 코드를 개발하면 해당 구현을 나중에 사용할 수 있도록 저장할 수 있습니다:

```
// ./skills/save-sheet-as-csv.ts에서
import * as gdrive from './servers/google-drive';
export async function saveSheetAsCsv(sheetId: string) {
  const data = await gdrive.getSheet({ sheetId });
  const csv = data.map(row => row.join(',')).join('\n');
  await fs.writeFile(`./workspace/sheet-${sheetId}.csv`, csv);
  return `./workspace/sheet-${sheetId}.csv`;
}
```

코드 실행은 자체적인 복잡성을 도입한다는 점에 유의하세요. 에이전트가 생성한 코드를 실행하려면 적절한 샌드박싱, 리소스 제한 및 모니터링이 있는 안전한 실행 환경이 필요합니다. 이러한 인프라 요구 사항은 직접 도구 호출이 피하는 운영 오버헤드 및 보안 고려 사항을 추가합니다. 코드 실행의 이점(토큰 비용 감소, 지연 시간 단축, 도구 구성 개선)은 이러한 구현 비용과 비교 검토되어야 합니다.
