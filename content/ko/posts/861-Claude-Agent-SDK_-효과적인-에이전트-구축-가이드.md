Claude Agent SDK는 Claude Code를 기반으로 강력한 에이전트를 만들 수 있도록 돕는 도구 모음입니다. 이 글에서는 시작 방법과 모범 사례를 소개합니다.

작년에 고객들과 함께 효과적인 에이전트를 구축하는 방법을 공유했습니다. 그 이후 Anthropic의 개발자 생산성 향상을 위해 자체 개발한 에이전트 코딩 솔루션인 Claude Code를 출시했습니다.

지난 몇 달 동안 Claude Code는 단순한 코딩 도구를 넘어섰습니다. Anthropic에서는 심층 리서치, 동영상 제작, 메모 작성 등 코딩이 아닌 다양한 용도로 활용하고 있습니다. 실제로 현재 대부분의 주요 에이전트 루프를 구동하고 있습니다.

다시 말해, Claude Code를 구동하는 에이전트 하네스(Claude Code SDK)가 다른 유형의 에이전트들도 구동할 수 있다는 뜻입니다. 이러한 확장된 비전을 반영하기 위해 Claude Code SDK를 **Claude Agent SDK**로 명칭을 변경합니다.

이 글에서는 Claude Agent SDK를 개발한 이유, 이를 활용해 나만의 에이전트를 구축하는 방법, 그리고 저희 팀의 실제 배포 경험에서 나온 모범 사례를 공유합니다.

## Claude에게 컴퓨터 제공하기

Claude Code의 핵심 설계 원칙은 **Claude가 프로그래머들이 매일 사용하는 도구를 동일하게 사용할 수 있어야 한다**는 것입니다. 코드베이스에서 적절한 파일을 찾고, 파일을 작성하고 편집하며, 코드를 린트하고, 실행하고, 디버깅하고, 편집하며, 때로는 코드가 성공할 때까지 이러한 작업을 반복적으로 수행할 수 있어야 합니다.

Claude에게 사용자의 컴퓨터(터미널을 통해) 접근 권한을 제공함으로써 프로그래머처럼 코드를 작성하는 데 필요한 모든 것을 갖추게 됐습니다.

하지만 이는 Claude Code의 Claude를 코딩이 아닌 작업에서도 효과적으로 만들었습니다. bash 명령어 실행, 파일 편집, 파일 생성 및 검색 도구에 대한 접근 권한을 제공함으로써 Claude는 CSV 파일을 읽고, 웹을 검색하고, 시각화를 구축하고, 지표를 해석하는 등 모든 종류의 디지털 작업을 수행할 수 있습니다. 즉, 컴퓨터를 사용하는 범용 에이전트를 만들 수 있습니다.

Claude Agent SDK의 핵심 설계 원칙은 **에이전트에게 컴퓨터를 제공해 사람처럼 일하도록 하는 것**입니다.

## 새로운 유형의 에이전트 만들기

Claude에게 컴퓨터를 제공하면 이전보다 더 효과적인 에이전트를 구축할 수 있다고 믿습니다. 예를 들어, SDK를 사용하면 개발자들은 다음과 같은 것들을 만들 수 있습니다:

**금융 에이전트**: 포트폴리오와 목표를 이해하고, 외부 API에 접근하고, 데이터를 저장하고, 계산을 위한 코드를 실행해 투자를 평가하는 에이전트

**개인 비서 에이전트**: 여행을 예약하고 일정을 관리하며, 약속을 잡고, 브리핑을 준비하는 등 내부 데이터 소스에 연결하고 애플리케이션 간 맥락을 추적하는 에이전트

**고객 지원 에이전트**: 고객 서비스 티켓처럼 모호한 사용자 요청을 처리하고, 사용자 데이터를 수집하고 검토하며, 외부 API에 연결하고, 사용자에게 메시지를 보내고, 필요시 사람에게 에스컬레이션하는 에이전트

**심층 리서치 에이전트**: 대규모 문서 컬렉션을 검색하고, 여러 소스의 정보를 분석 및 종합하며, 파일 간 데이터를 상호 참조하고, 상세한 보고서를 생성하는 종합적인 리서치를 수행하는 에이전트

그 외에도 더 많습니다. 근본적으로 SDK는 자동화하려는 모든 워크플로우에 필요한 에이전트를 구축할 수 있는 기본 요소를 제공합니다.

## 에이전트 루프 구축하기

Claude Code에서 Claude는 특정 피드백 루프에서 작동합니다: **맥락 수집 → 행동 실행 → 작업 검증 → 반복**

이는 다른 에이전트와 그들이 갖춰야 할 기능을 생각하는 데 유용한 방법을 제공합니다. 이를 설명하기 위해 Claude Agent SDK에서 이메일 에이전트를 구축하는 예시를 살펴보겠습니다.

### 1. 맥락 수집

에이전트를 개발할 때는 단순히 프롬프트만 제공하는 것이 아니라, 에이전트가 자체적으로 맥락을 가져오고 업데이트할 수 있어야 합니다. SDK의 기능이 어떻게 도움이 되는지 살펴보겠습니다.

**에이전트 검색과 파일 시스템**

파일 시스템은 모델의 맥락으로 가져올 수 있는 정보를 나타냅니다.

Claude가 로그나 사용자가 업로드한 파일처럼 큰 파일을 만나면, grep이나 tail 같은 bash 스크립트를 사용해 이를 맥락에 로드할 방법을 결정합니다. 본질적으로 에이전트의 폴더와 파일 구조가 일종의 맥락 엔지니어링이 됩니다.

이메일 에이전트는 이전 대화를 'Conversations'라는 폴더에 저장할 수 있습니다. 그러면 관련 질문을 받았을 때 이전 대화를 검색해 맥락을 찾을 수 있습니다.

**시맨틱 검색**

시맨틱 검색은 일반적으로 에이전트 검색보다 빠르지만 정확도가 떨어지고, 유지 관리가 어려우며, 투명성이 낮습니다. 관련 맥락을 '청킹'하고, 이러한 청크를 벡터로 임베딩한 다음, 해당 벡터를 쿼리해 개념을 검색하는 방식입니다. 이러한 한계를 고려할 때, 에이전트 검색부터 시작하고 더 빠른 결과나 더 많은 변형이 필요한 경우에만 시맨틱 검색을 추가할 것을 권장합니다.

**서브에이전트**

Claude Agent SDK는 기본적으로 서브에이전트를 지원합니다. 서브에이전트는 두 가지 주요 이유로 유용합니다.

첫째, 병렬화가 가능합니다. 여러 서브에이전트를 동시에 실행해 서로 다른 작업을 처리할 수 있습니다.

둘째, 맥락 관리에 도움이 됩니다. 서브에이전트는 자체적으로 격리된 맥락 윈도우를 사용하며, 전체 맥락이 아닌 관련 정보만 오케스트레이터에게 전달합니다. 이는 대부분이 유용하지 않은 대량의 정보를 걸러내야 하는 작업에 이상적입니다.

이메일 에이전트를 설계할 때 '검색 서브에이전트' 기능을 제공할 수 있습니다. 그러면 이메일 에이전트가 여러 검색 서브에이전트를 병렬로 실행해 각각 이메일 히스토리에 대해 서로 다른 쿼리를 실행하고, 전체 이메일 스레드가 아닌 관련 발췌 부분만 반환하도록 할 수 있습니다.

**컴팩션**

에이전트가 오랜 시간 실행될 때는 맥락 유지가 중요합니다. Claude Agent SDK의 컴팩트 기능은 맥락 한계에 근접하면 이전 메시지를 자동으로 요약해 에이전트가 맥락을 소진하지 않도록 합니다. 이는 Claude Code의 컴팩트 슬래시 명령어를 기반으로 합니다.

### 2. 행동 실행

맥락을 수집한 후에는 에이전트에게 유연한 행동 실행 방법을 제공해야 합니다.

**도구**

도구는 에이전트 실행의 주요 구성 요소입니다. 도구는 Claude의 맥락 윈도우에서 두드러지게 표시되므로, Claude가 작업을 완료하는 방법을 결정할 때 고려하는 주요 행동입니다. 즉, 맥락 효율성을 극대화하기 위해 도구를 어떻게 설계하는지 신중하게 생각해야 합니다.

따라서 도구는 에이전트가 수행하기를 원하는 주요 행동이어야 합니다. Claude Agent SDK에서 커스텀 도구를 만드는 방법을 알아보세요.

이메일 에이전트의 경우, "fetchInbox"나 "searchEmails" 같은 도구를 에이전트의 가장 자주 사용하는 주요 행동으로 정의할 수 있습니다.

**Bash와 스크립트**

Bash는 에이전트가 컴퓨터를 사용해 유연한 작업을 수행할 수 있도록 하는 범용 도구로 유용합니다.

이메일 에이전트의 경우, 사용자가 첨부 파일에 중요한 정보를 저장했을 수 있습니다. Claude는 코드를 작성해 PDF를 다운로드하고, 텍스트로 변환한 다음, 검색해서 유용한 정보를 찾을 수 있습니다.

**코드 생성**

Claude Agent SDK는 코드 생성에 뛰어나며, 그럴 만한 이유가 있습니다. 코드는 정확하고, 조합 가능하며, 무한히 재사용할 수 있어 복잡한 작업을 안정적으로 수행해야 하는 에이전트에 이상적인 출력물입니다.

에이전트를 구축할 때 고려해야 할 질문: 어떤 작업이 코드로 표현되면 이점이 있을까요? 종종 그 답이 상당한 기능을 열어줍니다.

예를 들어, 최근 Claude.AI에서 출시한 파일 생성 기능은 전적으로 코드 생성에 의존합니다. Claude는 Python 스크립트를 작성해 Excel 스프레드시트, PowerPoint 프레젠테이션, Word 문서를 생성하며, 다른 방법으로는 달성하기 어려운 일관된 서식과 복잡한 기능을 보장합니다.

이메일 에이전트의 경우, 사용자가 수신 이메일에 대한 규칙을 만들 수 있도록 하고 싶을 수 있습니다. 이를 위해 해당 이벤트에서 실행할 코드를 작성할 수 있습니다.

**MCP**

Model Context Protocol(MCP)은 외부 서비스에 대한 표준화된 통합을 제공하며, 인증과 API 호출을 자동으로 처리합니다. 즉, 직접 통합 코드를 작성하거나 OAuth 흐름을 관리하지 않고도 Slack, GitHub, Google Drive, Asana 같은 도구에 에이전트를 연결할 수 있습니다.

이메일 에이전트의 경우, 팀 맥락을 이해하기 위해 Slack 메시지를 검색하거나, 고객 요청을 처리하도록 누군가 이미 할당되었는지 Asana 작업을 확인하고 싶을 수 있습니다. MCP 서버를 사용하면 이러한 통합이 즉시 작동합니다. 에이전트가 단순히 search\_slack\_messages나 get\_asana\_tasks 같은 도구를 호출하면 MCP가 나머지를 처리합니다.

MCP 생태계가 성장하면서 사전 구축된 통합이 제공되므로 에이전트에 새로운 기능을 빠르게 추가할 수 있으며, 에이전트 동작에 집중할 수 있습니다.

### 3. 작업 검증

Claude Code SDK는 작업을 평가함으로써 에이전트 루프를 완성합니다. 자체 출력을 확인하고 개선할 수 있는 에이전트는 근본적으로 더 안정적입니다. 실수가 누적되기 전에 잡아내고, 방향이 틀어지면 스스로 수정하며, 반복하면서 개선됩니다.

핵심은 Claude에게 작업을 평가할 구체적인 방법을 제공하는 것입니다. 효과적이라고 판단한 세 가지 접근 방식이 있습니다:

**규칙 정의**

가장 좋은 피드백 형태는 출력에 대해 명확하게 정의된 규칙을 제공한 다음, 어떤 규칙이 실패했고 그 이유를 설명하는 것입니다.

코드 린팅은 규칙 기반 피드백의 훌륭한 형태입니다. 피드백이 상세할수록 좋습니다. 예를 들어, 순수 JavaScript를 생성하는 것보다 TypeScript를 생성하고 린트하는 것이 일반적으로 더 좋습니다. 여러 추가 피드백 레이어를 제공하기 때문입니다.

이메일을 생성할 때, Claude가 이메일 주소가 유효한지 확인하고(그렇지 않으면 오류 발생), 사용자가 이전에 그들에게 이메일을 보낸 적이 있는지 확인하도록(그렇다면 경고 발생) 할 수 있습니다.

**시각적 피드백**

UI 생성이나 테스트처럼 시각적 작업을 완료하기 위해 에이전트를 사용할 때, 시각적 피드백(스크린샷이나 렌더링 형태)이 도움이 될 수 있습니다. 예를 들어, HTML 서식이 있는 이메일을 보낼 때, 생성된 이메일을 스크린샷으로 찍어 모델에 제공해 시각적 검증과 반복적 개선을 할 수 있습니다. 그러면 모델이 시각적 출력이 요청된 것과 일치하는지 확인합니다.

예를 들어:

- **레이아웃** - 요소가 올바르게 배치되었나요? 간격이 적절한가요?
- **스타일링** - 색상, 글꼴, 서식이 의도한 대로 나타나나요?
- **콘텐츠 계층** - 정보가 적절한 강조와 함께 올바른 순서로 제시되었나요?
- **반응성** - 깨지거나 좁아 보이나요? (단일 스크린샷은 뷰포트 정보가 제한적이긴 하지만)

Playwright 같은 MCP 서버를 사용하면 이러한 시각적 피드백 루프를 자동화할 수 있습니다. 렌더링된 HTML의 스크린샷을 찍고, 다양한 뷰포트 크기를 캡처하며, 심지어 대화형 요소를 테스트하는 것까지 모두 에이전트의 워크플로우 내에서 가능합니다.

**LLM을 평가자로 활용**

다른 언어 모델에게 에이전트의 출력을 모호한 규칙을 기반으로 "평가"하도록 할 수도 있습니다. 이는 일반적으로 견고한 방법은 아니며 지연 시간 측면에서 큰 트레이드오프가 있을 수 있지만, 성능 향상이 비용 대비 가치가 있는 애플리케이션에서는 도움이 될 수 있습니다.

이메일 에이전트는 별도의 서브에이전트로 초안의 톤을 평가해 사용자의 이전 메시지와 잘 맞는지 확인할 수 있습니다.

## 에이전트 테스트 및 개선

에이전트 루프를 몇 번 거친 후에는 에이전트를 테스트하고 작업에 잘 준비되어 있는지 확인하는 것이 좋습니다. 에이전트를 개선하는 가장 좋은 방법은 출력물, 특히 실패한 경우를 주의 깊게 살펴보고, 에이전트의 입장에서 생각해보는 것입니다. 작업에 적합한 도구를 가지고 있나요?

에이전트가 작업에 잘 준비되어 있는지 평가할 때 물어볼 몇 가지 질문입니다:

- 에이전트가 작업을 잘못 이해한다면, 주요 정보가 누락되었을 수 있습니다. 검색 API의 구조를 변경해 필요한 정보를 더 쉽게 찾을 수 있도록 할 수 있을까요?
- 에이전트가 작업에 반복적으로 실패한다면, 도구 호출에 공식적인 규칙을 추가해 실패를 식별하고 수정할 수 있을까요?
- 에이전트가 오류를 수정할 수 없다면, 문제에 다르게 접근할 수 있는 더 유용하거나 창의적인 도구를 제공할 수 있을까요?
- 기능을 추가하면서 에이전트의 성능이 변동한다면, 고객 사용 패턴을 기반으로 프로그래밍 방식 평가(또는 evals)를 위한 대표적인 테스트 세트를 구축하세요.

## 시작하기

Claude Agent SDK는 Claude에게 파일을 작성하고, 명령어를 실행하며, 작업을 반복할 수 있는 컴퓨터 접근 권한을 제공해 자율 에이전트를 더 쉽게 구축할 수 있도록 합니다.

에이전트 루프(맥락 수집, 행동 실행, 작업 검증)를 염두에 두고, 배포하고 반복하기 쉬운 안정적인 에이전트를 구축할 수 있습니다.

오늘부터 Claude Agent SDK를 시작할 수 있습니다. 이미 SDK를 기반으로 구축하고 있는 개발자라면, 이 가이드를 따라 최신 버전으로 마이그레이션하는 것을 권장합니다.

**핵심 요약**: Claude Agent SDK는 에이전트에게 컴퓨터를 제공해 파일 작성, 명령 실행, 반복 작업이 가능하도록 하며, 맥락 수집 → 행동 실행 → 작업 검증의 루프를 통해 금융, 리서치, 고객 지원 등 다양한 분야의 자율 에이전트를 구축할 수 있습니다.
